# Brief: Pet Voice & Audio Feature (voice)

## Overview
ฟีเจอร์เสียงน้องอ๊บ (`voice`) ของแอป PetPal Health ทำหน้าที่เพิ่มเสียงพากย์น่ารักกวนๆ ให้กับตัวละครสัตว์เลี้ยงตามบริบทกิจกรรมสุขภาพ (การเดิน `steps`, การกิน `food`, การดื่มน้ำ `water`) เพื่อสร้างแรงจูงใจ ให้กำลังใจ และแซวผู้ใช้แบบเป็นกันเอง โดยไม่เป็นการบลูลี่ พร้อมระบบขอสิทธิ์เมื่อเข้าใช้งานครั้งแรก และปุ่มตั้งค่าเปิด/ปิดเสียงกับ Shortcut ควบคุมระบบแจ้งเตือนที่มีอยู่เดิมที่มุมขวาบน

## 1. Character & Voice Specification (สเปกเนื้อเสียง)
- **Voice Character:** ผู้ชายแกล้งทำเสียงผู้หญิง โทนเสียงอบอุ่น กวนตีนเบาๆ เป็นกันเอง (Playful & Supportive Trolling)
- **Technical Audio Setup:**
  - **Audio Source:** ไฟล์เสียงสั้น `.mp3` จัดเก็บแบบ Local Assets (`assets/audio/voice/`)
  - **Audio Tuning:** Base Male Voice ปรับ Pitch Shift +3 ถึง +4 Semitones
  - **Emotional Tone:** มีทั้งโหมดขี้เกียจ (แซวขำๆ), โหมดใกล้สำเร็จ (เชียร์อัพตื่นเต้น), และโหมดสำเร็จ (ชมเชยสูงสุด)

## 2. Audio Context & Script Matrix (ตารางคำพูดตามบริบท - ใช้ชื่อไฟล์มาตรฐาน)
- **Steps (< 35%):** `voice_steps_lazy.mp3` — `"แหม... นอนเก่งขนาดนี้ นึกว่าจำศีลอยู่ซะอีก ลุกขึ้นมาขยับขาหน่อยเร้ว เดี๋ยวร่างจะติดโซฟาเอานะยูว์"`
- **Steps (70% - 99%):** `voice_steps_encouraging.mp3` — `"ฮั่นแน่! อีกนิดเดียวก็จะครบเป้าหมายแล้วนะเนี่ย ขาเริ่มสั่นยังคะคนดี ฮึบอีกนิด เดี๋ยวมีรางวัลให้!"`
- **Steps (≥ 100%):** `voice_steps_success.mp3` — `"โอโห้! วันนี้เดินเยอะจนนับขาแทบไม่ทัน เก่งมากค่ะคนดี ขาไม่พังใช่ไหมเนี่ย วันนี้พักผ่อนตามสบายเลยนะ!"`
- **Food (เกิน > 100 kcal):** `voice_food_overeating.mp3` — `"พุงจะแตกตายอยู่แล้วนะแม่คุณ! พอเถอะน้าคนดี เดี๋ยวพรุ่งนี้ค่อยลุยใหม่ (แต่ตอนนี้อิ่มแปล้เลยสิเนี่ย)"`
- **Water (< 3 แก้ว):** `voice_water_low.mp3` — `"คอแห้งเป็นผงละเนี่ย ดื่มน้ำหน่อยเร้ว เดี๋ยวหน้าเหี่ยวไม่รู้ด้วยนะ พี่อ๊บเป็นห่วงนะเนี่ย"`
- **Water (≥ 8 แก้ว):** `voice_water_success.mp3` — `"ดื่มน้ำเก่งมาก! ผิวพรรณเปล่งปลั่งออร่าจับเลยแบบนี้ เอาใจไปเลยสิคะคนดี!"`

## 3. UI/UX Permissions & Settings Flow
- **First Launch Permission Dialog:** เมื่อผู้ใช้เข้าสู่หน้า Home ครั้งแรกหลัง Onboarding ให้แสดง Popup ถามเปิดใช้งานเสียง:

## 4. Edge cases

| ID | สถานการณ์ | ผลที่คาดหวัง |
|---|---|---|
| EC-1 | ผู้ใช้เปิดโหมดปิดเสียง (Mute Mode / Silent) หรือลดเสียงสื่อเป็น 0 บนมือถือ | ระบบต้องเล่นไฟล์เสียงในเบื้องหลังตามโค้ดปกติโดยไม่เกิดแอปพลิเคชันแครช (Crash) แม้ผู้ใช้ไม่ได้ยินเสียง |
| EC-2 | มีเหตุการณ์กระตุ้นเสียงพากย์หลายบริบทพร้อมกัน ( Audio Queue / Overlap ) เช่น บันทึกน้ำและก้าวเดินเสร็จในเวลาไล่เลี่ยกัน | ระบบต้องจัดคิวการเล่นเสียง (Audio Queue) เล่นทีละไฟล์ตามลำดับก่อนหลัง ไม่เล่นทับซ้อนกัน (No Audio Overlap) |
| EC-3 | ไฟล์เสียง `.mp3` ใน Local Assets เสียหายหรือไม่พบไฟล์ (Missing Asset) | ระบบต้องดักจับข้อผิดพลาด (Exception Handling) ข้ามการเล่นเสียงนั้นไปเงียบๆ โดยไม่กระทบการทำงานหลักของแอป |
| EC-4 | อุปกรณ์ของผู้ใช้อยู่ในสถานะออฟไลน์ (Offline Local Storage) | ระบบสามารถโหลดและเล่นไฟล์เสียง `.mp3` จาก Local Assets (`assets/audio/voice/`) ได้ปกติ 100% โดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต |
| EC-5 | ผู้ใช้กดคลิกเปิด/ปิด Toggle Switch รัวๆ ในเวลาสั้นๆ (Toggle Debounce) | ระบบต้องมีกลไก Debounce (หน่วงเวลา 300 มิลลิวินาที) เพื่อป้องกันการบันทึกค่าซ้ำซ้อนและป้องการส่งคำขอชนกัน |

## 5. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ระบบบันทึกเสียงผู้ใช้หรือระบบแปลงข้อความ Text-to-Speech (TTS) แบบ Real-time บนคลาวด์
- การปรับเปลี่ยนคาแรคเตอร์เสียงหรือตัวเลือก Pitch Shift เพิ่มเติมจากการตั้งค่าในระบบ
- ระบบแปลภาษาเสียงพากย์เป็นภาษาอื่นนอกเหนือจากภาษาไทย
