- ข้อมูลและหลอดพลังงานจะถูกรีเซ็ตเป็น 0 ตอน 05:00 น. (ตี 5) ของทุกวัน

ฟีเจอร์บันทึกการกินน้ำช่วยให้ผู้ใช้สามารถบันทึกปริมาณน้ำดื่มในแต่ละวันเพื่อสุขภาพของตนเอง พร้อมทั้งเชื่อมโยงกับหลอดพลังงานและอารมณ์ของสัตว์เลี้ยงในแอป PetPal Health เพื่อสร้างแรงจูงใจในการดื่มน้ำให้ครบ 8 แก้วต่อวัน ข้อมูลทั้งหมดจะถูกประมวลผลและเก็บรักษาบน Local Storage พร้อมระบบ Anti-Spam ป้องกันการกดบันทึกถี่เกินไป

## 2. User stories

| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | เจ้าของสัตว์เลี้ยง | กดบันทึกปริมาณการดื่มน้ำของฉัน (1 แก้ว) | เพิ่มหลอดพลังงานน้ำและดูแลอารมณ์ของสัตว์เลี้ยง |
| US-2 | เจ้าของสัตว์เลี้ยง | เห็นสถานะและอารมณ์ของสัตว์เลี้ยงที่เปลี่ยนไปตามปริมาณน้ำที่ดื่ม | ทราบว่าสัตว์เลี้ยงมีความสุขหรือต้องการการดูแลเพิ่มขึ้น |
| US-3 | เจ้าของสัตว์เลี้ยง | ถูกแจ้งเตือนและจำกัดสิทธิ์เมื่อกดบันทึกน้ำถี่เกินไป | ป้องกันการบันทึกข้อมูลที่ผิดพลาด (Anti-Spam) |
| US-4 | ระบบ | รีเซ็ตข้อมูลจำนวนแก้ว หลอดพลังงาน และเวลาบันทึกล่าสุดเป็น 0 อัตโนมัติ | เริ่มต้นวันใหม่ได้อย่างถูกต้องในเวลา 05:00 น. ของทุกวัน |

## 3. Acceptance criteria

| ID | อ้างถึง | เงื่อนไข (ก่อน /เมื่อ /แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | กำหนดให้ 1 แก้ว = 12.5% เมื่อผู้ใช้กดปุ่ม "บันทึกน้ำ" 1 ครั้ง | หลอดพลังงานน้ำเพิ่มขึ้น 12.5% และจำนวนแก้วเพิ่มขึ้น 1 แก้วทันที |
| AC-2 | US-2 | เมื่อหลอดพลังงานน้ำอยู่ที่ 0% - 29% (0 - 2 แก้ว) | สัตว์เลี้ยงแสดงสถานะ "เหี่ยวเฉา ป่วย ใกล้ตาย" |
| AC-3 | US-2 | เมื่อหลอดพลังงานน้ำอยู่ที่ 30% - 59% (3 - 4 แก้ว) | สัตว์เลี้ยงแสดงสถานะ "เริ่มเพลีย อ่อนแรง แลบลิ้น" |
| AC-4 | US-2 | เมื่อหลอดพลังงานน้ำอยู่ที่ 60% - 100% (5 - 8+ แก้ว) | สัตว์เลี้ยงแสดงสถานะ "สดชื่น ร่าเริง มีความสุข" และหยุดเพิ่มหลอดพลังงานเมื่อถึง 100% (8 แก้วขึ้นไป) |
| AC-5 | US-3 | เมื่อผู้ใช้กดบันทึกน้ำครบ 2 ครั้งภายในช่วงเวลา 5 นาที และพยายามกดครั้งที่ 3 | ระบบแสดงข้อความแจ้งเตือน Cooldown และไม่อนุญาตให้เพิ่มจำนวนแก้วจนกว่าจะครบ 5 นาทีจากครั้งแรก |
| AC-6 | US-4 | เมื่อนาฬิกาของระบบถึงเวลา 05:00:00 น. ของวันใหม่ | จำนวนแก้วน้ำและหลอดพลังงานถูกรีเซ็ตกลับเป็น 0 (0%) และล้างค่าเวลาบันทึกล่าสุดทันที |

## 4. Edge cases

| ID | สถานการณ์ | ผลที่คาดหวังที่ทดสอบได้ |
|---|---|---|
| EC-1 | ผู้ใช้กดบันทึกน้ำครั้งที่ 1, รอ 4 นาที 59 วินาที แล้วกดครั้งที่ 2 และ 3 ติดกันทันที | การกดครั้งที่ 3 จะถูกบล็อกด้วยระบบ Cooldown เนื่องจากนับระยะเวลา 5 นาทีจากจุดเริ่มต้นของการกดครั้งที่ 1 หรือต้องรอตามเงื่อนไข Anti-Spam (สูงสุด 2 ครั้งต่อ 5 นาที) |
| EC-2 | ผู้ใช้ดื่มน้ำสะสมถึง 10 แก้ว (125%) | หลอดพลังงานแสดงผลสูงสุดที่ 100% และสถานะสัตว์เลี้ยงคง 100% (สดชื่น ร่าเริง มีความสุข) โดยไม่แสดงผลเกิน 100% |
| EC-3 | แอปพลิเคชันถูกปิด (Force Close) หรือรีสตาร์ทเครื่องในระหว่างวัน (เช่น เวลา 12:00 น.) | ข้อมูลจำนวนแก้ว หลอดพลังงาน (%) และประทับเวลา (Timestamp) ล่าสุด ยังคงถูกต้องและดึงมาจาก Local Storage โดยไม่มีค่าหายไป |

## 5. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ไม่มีระบบลดพลังงานน้ำตามเวลาระหว่างวัน (Decay)
- ยังไม่ต่อ Backend หรือ Server ภายนอก (ใช้ Local Storage เท่านั้น)
- ยังไม่มีระบบ Social / ดูเพื่อนร่วมกัน
- ยังไม่มีระบบซื้อของแต่งตัวสัตว์เลี้ยงเพิ่มเติม

## 6. ข้อมูลที่ใช้ (ข้อมูลสมมติเท่านั้น)

| ข้อมูล | ชนิด/หน่วย | เก็บที่ไหน |
|---|---|---|
| water_count | Integer (แก้ว) | Local Storage (SharedPreferences / Hive) |
| water_energy_percentage | Float (%) | Local Storage (SharedPreferences / Hive) |
| last_log_timestamps | List of Timestamps (ISO 8601) | Local Storage (SharedPreferences / Hive) |
| pet_mood_status | String | Local Storage (SharedPreferences / Hive) |

## 7. คำถามที่ยังเปิดอยู่
- ทีมพัฒนาควรใช้ SharedPreferences หรือ Hive เป็นLocal Storage หลักสำหรับฟีเจอร์นี้ เพื่อให้ประสิทธิภาพในการอ่านเขียน Timestamp และการจัดการ Cooldown ดีที่สุดใน Flutter?
- ข้อความแจ้งเตือน (Error Message) เมื่อผู้ใช้กดติด Cooldown (เข้าเงื่อนไข Anti-Spam) ควรแสดงเป็น Snackbar หรือ Pop-up Dialog?
