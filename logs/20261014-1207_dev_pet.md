| BUG-PET-1: บันทึกน้ำ/เพิ่มก้าวสำเร็จในครั้งที่ทำให้สถานะเปลี่ยน (water 3→4, 6→7; steps ข้าม 35%) → ไม่ cheer และจังหวะหายใจ/กะพริบเริ่มใหม่ | key `ValueKey('water_pet_image_${mood.name}')` / `ValueKey('steps_pet_image_${status.name}')` อยู่บน PetCharacter เอง → key เปลี่ยน → Flutter สร้าง State ใหม่ → `initState` เห็น cheerTrigger ที่เพิ่มแล้ว (cheer เล่นเฉพาะใน `didUpdateWidget`) | PetCharacter ได้ `key: _petKey` (GlobalKey สร้างครั้งเดียวต่อ State ของหน้าจอ) → State คงอยู่และถูก reparent ไปใต้ wrapper ใหม่เมื่อ key ฟีเจอร์เปลี่ยน → `didUpdateWidget` เห็น cheerTrigger เปลี่ยน → cheer · key ฟีเจอร์ย้ายไปที่ `KeyedSubtree` ที่ห่อ PetCharacter (ชื่อ key ไม่เปลี่ยน) | app/lib/features/water/screens/water_home_screen.dart, app/lib/features/steps/screens/steps_dashboard_screen.dart |

เหตุที่เลือก GlobalKey + KeyedSubtree: ทางเดียวที่ทำให้ PetCharacter มี State เดิมต่อไปในขณะที่ key ฟีเจอร์ยังเปลี่ยนตามสถานะ (ถ้าใช้ ValueKey คงที่บน PetCharacter แต่ wrapper ที่ key เปลี่ยน ทั้ง subtree จะถูกสร้างใหม่อยู่ดี) · ไม่เลือกการทำ Key ปลอมที่ `==` เท่ากับ ValueKey หลายค่า เพราะผิดสัญญา `==`/`hashCode` (ทำโค้ดบิดเพื่อเทสต์)

### Key / locator สำหรับ QA (หลังแก้)
- `find.byKey(ValueKey('water_pet_image_<mood>'))` / `find.byKey(ValueKey('steps_pet_image_<status>'))` ยังใช้ได้ (findsOneWidget) แต่ widget ที่ได้คือ `KeyedSubtree` ไม่ใช่ `PetCharacter`
- หาตัว PetCharacter: `find.descendant(of: find.byKey(featureKey), matching: find.byType(PetCharacter))` แล้ว `tester.widget<PetCharacter>(...)`
- `find.descendant(of: featureKey, matching: find.byKey(PetKeys.painter))` และการตรวจ "ไม่มี Image ใต้ key" ใช้ได้เหมือนเดิม
