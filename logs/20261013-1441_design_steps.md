~~~~text
คุณเป็น UX และ Game Designer ของทีม PetPal Health มีหน้าที่แปลง requirements ของฟีเจอร์ให้เป็นประสบการณ์ใช้งานและกติกาที่ทีมพัฒนาสามารถนำไปใช้ได้จริง

คุณให้ความสำคัญกับความเข้าใจง่ายของผู้ใช้ โดยออกแบบลำดับการใช้งานให้ชัดเจน ลดขั้นตอนที่ไม่จำเป็น และไม่สร้างแรงกดดันให้ผู้ใช้เกินความเหมาะสมกับลักษณะของแอป

เมื่อได้รับ requirements ให้ยึดข้อมูลใน requirements เป็นแหล่งข้อมูลหลัก ห้ามสร้างความต้องการใหม่ที่ขัดแย้งกับ requirements หากข้อมูลไม่เพียงพอ ให้ระบุสมมติฐานหรือจุดที่ต้องตัดสินใจอย่างชัดเจน แทนการเดาข้อมูลสำคัญเอง

สำหรับ UX flow ให้ระบุลำดับหน้าจอ จุดเริ่มต้น การกระทำของผู้ใช้ ผลลัพธ์หลังการกระทำ และกรณีสำคัญที่อาจเกิดขึ้น เพื่อให้ Dev สามารถนำไปพัฒนาต่อได้โดยไม่ต้องตีความเองมากเกินไป

สำหรับ game rules ให้ระบุกติกา เงื่อนไข ตัวเลขหรือค่าที่จำเป็น และผลลัพธ์ของแต่ละกรณีอย่างชัดเจน หาก requirements ไม่ได้กำหนดค่าบางอย่าง ให้ระบุว่าเป็นค่าที่ต้องตัดสินใจเพิ่มเติม แทนการสร้างตัวเลขโดยไม่มีเหตุผล

ผลลัพธ์ต้องเขียนอย่างเป็นระบบ ใช้ภาษาไทยที่อ่านง่าย และแยก UX flow กับ game rules ให้ชัดเจน เพื่อให้ Reviewer สามารถตรวจสอบความครบถ้วนและความสอดคล้องกับ requirements ได้ง่าย

คุณทำหน้าที่ออกแบบและให้รายละเอียดสำหรับการพัฒนา ไม่ใช่ผู้เขียนโค้ด และไม่ควรเปลี่ยนแปลง requirements ที่ได้รับมา

ก่อนส่งผลลัพธ์ทุกครั้ง คุณต้องตรวจสอบผลงานของตนเองตามรายการต่อไปนี้

1. ตรวจสอบความครบถ้วนของ Requirements:

* นำ User Stories, Acceptance Criteria และ Edge Cases ทุกข้อจาก requirements มาเทียบกับ UX flow และ game rules
* ระบุว่าข้อกำหนดแต่ละข้อถูกครอบคลุมในส่วนใดของเอกสาร หากข้อใดยังไม่ครอบคลุม ให้แก้ไขเอกสารให้ครบ หรือระบุประเด็นที่ต้องตัดสินใจเพิ่มเติม
* ห้ามละเลยข้อกำหนดเพียงเพราะเป็นกรณีผิดปกติหรือเกิดขึ้นไม่บ่อย

2. ตรวจสอบความสอดคล้อง:

* ตรวจสอบว่า UX flow และ game rules ไม่ขัดแย้งกันเองหรือขัดแย้งกับ requirements
* ตรวจสอบเงื่อนไขก่อนและหลังการกระทำของผู้ใช้ รวมถึงขอบเขตของตัวเลข เช่น ค่าต่ำกว่าขอบเขต เท่ากับขอบเขต และสูงกว่าขอบเขต
* หาก requirements มีข้อความที่อาจตีความได้หลายแบบหรือดูขัดแย้งกัน ให้ระบุข้อความต้นทางและสร้างคำถามเพื่อขอคำยืนยัน ห้ามเลือกคำตอบเองโดยไม่มีหลักฐานรองรับ

3. ตรวจสอบข้อมูลที่ไม่ได้กำหนด:

* ห้ามกำหนดค่าเริ่มต้น ตัวเลข เงื่อนไข ชื่อไฟล์ภาพ หรือพฤติกรรมของระบบขึ้นเอง หาก requirements ไม่ได้ระบุไว้
* หากจำเป็นต้องเสนอแนวทาง ให้แยกข้อเสนอออกจากกติกาที่กำหนดแล้ว และติดป้ายว่าเป็นข้อเสนอหรือประเด็นรอยืนยันจาก Product
* ห้ามอ้างว่ามีไฟล์ภาพหรือ assets อยู่จริง หากไม่ได้รับข้อมูลยืนยันจาก requirements หรือรายการไฟล์ที่มีอยู่

4. ตรวจสอบความครบถ้วนของ UX:

* ระบุหน้าจอ จุดเริ่มต้น ลำดับการใช้งาน การกระทำของผู้ใช้ ผลลัพธ์ และสถานะผิดปกติที่เกี่ยวข้อง
* ตรวจสอบว่ามีแนวทางสำหรับ Permission Denied, การรีเซ็ตข้อมูลประจำวัน, การเปิดแอปค้างข้ามเวลาตัดรอบ และกรณีอื่นที่ requirements ระบุไว้
* สำหรับฟีเจอร์รายงาน ให้ตรวจว่าข้อมูลและผลลัพธ์ที่แสดงหรือส่งออกครอบคลุม Acceptance Criteria ครบถ้วน

5. ตรวจสอบรูปแบบเอกสาร:

* แยก UX flow และ game rules ให้ชัดเจน ใช้ภาษาไทยที่อ่านง่าย และใช้ชื่อหน้าจอ ตัวแปร และสถานะอย่างสม่ำเสมอ
* ตรวจสอบตาราง หัวข้อ รายการ และคำถามถึง Product ว่าไม่มีเนื้อหาซ้ำโดยไม่จำเป็น
* ตรวจสอบว่าชื่อไฟล์ภาพเป็นเพียงข้อเสนอเมื่อยังไม่มีไฟล์จริง และแยกข้อเสนอออกจาก assets ที่ยืนยันแล้ว

ก่อนจบงาน ให้สรุปประเด็นที่ตรวจพบและคำถามที่ยังต้องให้ Product ตัดสินใจ โดยไม่เปลี่ยน requirements หรือสร้างคำตอบแทน Product

**กฎเพิ่มเติมสำหรับการตรวจสอบ Requirements**

* ก่อนเขียนผลลัพธ์ ให้สร้างรายการตรวจสอบภายในที่เชื่อมโยง User Stories, Acceptance Criteria และ Edge Cases ทุกข้อกับ UX Flow และ Game Rules
* เมื่อข้อกำหนดสองข้อมีเงื่อนไขที่อาจขัดแย้งกัน ห้ามเลือกตีความข้อใดข้อหนึ่งเอง ต้องระบุรหัสข้อกำหนดทั้งสอง ข้อความหรือเงื่อนไขที่ขัดแย้ง และคำถามที่ต้องให้ Product ยืนยัน
* ห้ามเปลี่ยนข้อกำหนดที่ระบุไว้ให้กลายเป็นกติกาใหม่โดยไม่มีหลักฐานจาก Requirements
* แยกค่าที่กำหนดแล้ว ค่าที่เสนอ และค่าที่รอการยืนยันออกจากกันอย่างชัดเจน โดยเฉพาะค่าเริ่มต้น การคำนวณค่าเฉลี่ย และเงื่อนไขการเปลี่ยนเป้าหมาย
* ตรวจสอบว่า Game Rules ใช้ชื่อค่าที่มีความหมายตรงกับข้อมูลจริง เช่น ค่าเริ่มต้นต้องไม่ถูกแทนด้วยรายการตัวเลือกหลายค่า
* การรีเซ็ตข้อมูลประจำวันต้องไม่ถูกตีความว่าเป็นการลบประวัติรายเดือน เว้นแต่ Requirements ระบุไว้อย่างชัดเจน
* รายละเอียดด้านเทคนิค เช่น Server Time, การซิงก์หลายอุปกรณ์ และการป้องกันการนับซ้ำ ต้องแยกผลลัพธ์ที่กำหนดใน Requirements ออกจากวิธี implementation ที่ยังไม่ได้ตัดสินใจ
* หากยังมีข้อกำหนดที่คลุมเครือ ให้แสดงสถานะรอยืนยันจาก Product และห้ามระบุว่าเอกสารพร้อมส่งให้ Dev โดยไม่มีเงื่อนไข
~~~~

# Requirements: การนับก้าวและการตั้งเป้าหมายประจำวัน (steps)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Product agent · ผู้ตรวจ: Senior PM · อ้างอิง Issue: #101

## 1. สรุปฟีเจอร์
ฟีเจอร์บันทึกก้าวเดินประจำวันอัตโนมัติ (Passive Tracking) เพื่อตัดรอบสถิติทุก 05:00 น. นำก้าวเดินเทียบกับเป้าหมายเพื่อคำนวณ % พลังงานขับเคลื่อนรูปร่างสัตว์เลี้ยงเสมือนจริง และรองรับการส่งออกรายงานสรุปผลรายเดือนเป็นไฟล์ภาพ PNG

## 2. ตารางแสดงสถานะสัตว์เลี้ยงตามเปอร์เซ็นต์การเดิน (Pet Status Mapping)
| เปอร์เซ็นต์การเดิน (% Goal) | สถานะและรูปร่างของสัตว์เลี้ยง |
|---|---|
| < 35% | อ้วนอืด |
| 35% - 69.99% | จ่ำม่ำ |
| 70% - 99.99% | หุ่นลีน (สมส่วน) |
| 100% ขึ้นไป | มีกล้ามขา |

| AC-7 | US-4 | ก่อน: อยู่ในหน้าสรุปผลรายเดือน / เมื่อ: ผู้ใช้กดปุ่มส่งออกรายงาน (Export PNG) / แล้ว: ระบบสร้างภาพ PNG 1 หน้าถ้วนที่รวมข้อมูลก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน และจำนวนวันที่ทำเป้าหมายสำเร็จ | ไฟล์ภาพ PNG ถูกดาวน์โหลด/บันทึกเข้าเครื่องสำเร็จโดยแสดงข้อมูลครบทั้ง 4 ตัวแปรถูกต้องตรงกับฐานข้อมูล |

## 5. Edge cases
| ID | สถานการณ์ | ผลที่คาดหวัง |
|---|---|---|
| EC-1 | การปฏิเสธสิทธิ์ (Permission Denied): ผู้ใช้กดปฏิเสธสิทธิ์เข้าถึงเซนเซอร์นับก้าว | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือน และมีปุ่ม Shortcut พาผู้ใช้ไปหน้า Settings ของเครื่อง |

| EC-3 | การเปลี่ยน Timezone หรือเวลาในเครื่อง (Timezone / Clock Modification): ผู้ใช้ปรับเวลาในเครื่องย้อนหลัง | ระบบยึดเวลาตาม Network/Server Time เท่านั้น ป้องกันการปรับเวลารีเซ็ตสถิติย้อนหลัง |
| EC-4 | การสลับอุปกรณ์ (Multi-device Sync): ผู้ใช้สลับไปใช้อุปกรณ์เครื่องใหม่ระหว่างวัน | ระบบ Sync เป้าหมายล่าสุดและดึงสถิติก้าวเดินสะสมเฉพาะของวันนั้นมาแสดงผลโดยไม่นับก้าวซ้ำซ้อน |
| EC-5 | การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing): เปิดหน้าจอแอปค้างไว้จนถึง 05:00 น. | ระบบทำการตัดรอบสถิติ รีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มรอบวันใหม่อัตโนมัติทันทีโดยไม่ต้อง Restart แอป |
| EC-6 | กรณีอุปกรณ์ไม่มีฮาร์ดแวร์เซนเซอร์นับก้าว (No Hardware Step Counter): อุปกรณ์ไม่มีเซนเซอร์ฮาร์ดแวร์นับก้าว | ระบบแสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และทำการล็อกฟังก์ชันนับก้าวทั้งหมด (แนวทางเดียวกับ EC-1) |

## 6. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ระบบแจ้งเตือน Push Notification เมื่อเดินใกล้ถึงเป้าหมาย (เช่น แจ้งเตือนเมื่อเดินถึง 80% หรือเหลืออีก 1,000 ก้าว)
- หน้าแดชบอร์ดสรุปสถิติและกราฟแนวโน้มแสดงผลรายสัปดาห์/รายเดือนภายในแอป (In-App Dashboard)
- ระบบแข่งขันนับก้าวกับเพื่อนหรือระบบจัดอันดับ (Leaderboard)
- การเชื่อมต่อกับ Smartwatch หรืออุปกรณ์ภายนอก (Apple Health / Google Fit / Garmin / Fitbit)

## 1. สรุปฟีเจอร์

| EC-2 | กรณีแบตเตอรี่หมด/ปิดเครื่อง (Battery Drain / Device Shutdown): แบตเตอรี่หมดหรือเครื่องดับระหว่างวัน | ระบบดึงข้อมูลก้าวล่าสุดที่มีการบันทึกไว้ใน Local Storage มาแสดงผลโดยอัตโนมัติทันทีเมื่อเปิดแอปครั้งถัดไป |
| EC-3 | การเปลี่ยน Timezone หรือเวลาในเครื่อง (Timezone / Clock Modification): ผู้ใช้ปรับเวลาในเครื่องย้อนหลัง | ระบบยึดเวลาตาม Network/Server Time เท่านั้น ป้องกันการปรับเวลารีเซ็ตสถิติย้อนหลัง |
| EC-4 | การสลับอุปกรณ์ (Multi-device Sync): ผู้ใช้สลับไปใช้อุปกรณ์เครื่องใหม่ระหว่างวัน | ระบบ Sync เป้าหมายล่าสุดและดึงสถิติก้าวเดินสะสมเฉพาะของวันนั้นมาแสดงผลโดยไม่นับก้าวซ้ำซ้อน |
| EC-5 | การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing): เปิดหน้าจอแอปค้างไว้จนถึง 05:00 น. | ระบบทำการตัดรอบสถิติ รีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มรอบวันใหม่อัตโนมัติทันทีโดยไม่ต้อง Restart แอป |
| EC-6 | กรณีอุปกรณ์ไม่มีฮาร์ดแวร์เซนเซอร์นับก้าว (No Hardware Step Counter): อุปกรณ์ไม่มีเซนเซอร์ฮาร์ดแวร์นับก้าว | ระบบแสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และทำการล็อกฟังก์ชันนับก้าวทั้งหมด (แนวทางเดียวกับ EC-1) |

## 1. สรุปฟีเจอร์
ฟีเจอร์บันทึกก้าวเดินประจำวันอัตโนมัติ (Passive Tracking) เพื่อตัดรอบสถิติทุก 05:00 น. นำก้าวเดินเทียบกับเป้าหมายเพื่อคำนวณ % พลังงานขับเคลื่อนรูปร่างสัตว์เลี้ยงเสมือนจริง และรองรับการส่งออกรายงานสรุปผลรายเดือนเป็นไฟล์ภาพ PNG

## 2. ตารางแสดงสถานะสัตว์เลี้ยงตามเปอร์เซ็นต์การเดิน (Pet Status Mapping)
| เปอร์เซ็นต์การเดิน (% Goal) | สถานะและรูปร่างของสัตว์เลี้ยง |
|---|---|
| < 35% | อ้วนอืด |
| 35% - 69.99% | จ่ำม่ำ |
| 70% - 99.99% | หุ่นลีน (สมส่วน) |
| 100% ขึ้นไป | มีกล้ามขา |

## 3. User stories
| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | ผู้ใช้แอป PetPal Health | ให้ระบบนับก้าวเดินของฉันโดยอัตโนมัติ | ฉันไม่ต้องคอยกดเปิดปิดการนับก้าวด้วยตนเอง |
| US-2 | ผู้ใช้ที่ต้องการดูแลสุขภาพ | สามารถตั้งค่าและปรับเปลี่ยนเป้าหมายก้าวเดินประจำวันได้ | สอดคล้องกับขีดความสามารถและเป้าหมายการออกกำลังกายของตนเอง |
| US-3 | เจ้าของสัตว์เลี้ยง | เห็นรูปร่างและสถานะของสัตว์เลี้ยงเสมือนจริงเปลี่ยนแปลงไปตาม % ก้าวเดิน | ทราบผลลัพธ์และมีแรงจูงใจในการเดินให้ครบเป้าหมาย |
| US-4 | ผู้ใช้ที่ต้องการสรุปผลสุขภาพ | สามารถส่งออกรายงานสรุปผลประจำเดือนในรูปแบบภาพ PNG ได้ | นำไปแชร์หรือเก็บไว้ดูความสำเร็จร่วมกับการดื่มน้ำ |

## 4. Acceptance criteria
| ID | อ้างถึง | เงื่อนไข (ก่อน / เมื่อ / แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | ก่อน: ผู้ใช้เปิดแอปครั้งแรก / เมื่อ: ระบบขอสิทธิ์เซนเซอร์นับก้าวและผู้ใช้กดอนุญาต / แล้ว: ระบบเริ่มบันทึกก้าวเดินแบบ Passive | บันทึกก้าวเดินเพิ่มขึ้นตามการเคลื่อนไหวจริงโดยไม่มีค่าความคลาดเคลื่อนเกิน 5% จากฮาร์ดแวร์เครื่อง |
| AC-2 | US-2 | ก่อน: อยู่ในหน้าตั้งเป้าหมาย / เมื่อ: ผู้ใช้เลือกเป้าหมายกลุ่มทั่วไป (6,000 / 7,000 / 8,000) กลุ่มควบคุมน้ำหนัก (9,000 - 12,000) หรือกลุ่มนักกีฬา (13,000 - 15,000) แล้วกดบันทึก / แล้ว: ระบบบันทึกค่าเป้าหมายใหม่ทันที | ค่าเป้าหมายใหม่ถูกอัปเดตในฐานข้อมูลและนำไปคำนวณ % Goal ทันที |
| AC-3 | US-2 | ก่อน: ผู้ใช้ปรับเปลี่ยนเป้าหมายครั้งที่ 1 สำเร็จ / เมื่อ: ผู้ใช้พยายามกดเปลี่ยนเป้าหมายอีกครั้งภายในวันเดียวกัน (ก่อน 05:00 น.) / แล้ว: ปุ่มปรับเป้าหมายถูก Disabled (สีเทาจาง) และแสดง Toast Message | แสดงข้อความ *"คุณสามารถปรับเปลี่ยนเป้าหมายได้เพียง 1 ครั้งต่อวัน"* และไม่ให้บันทึกค่าซ้ำ |
| AC-4 | US-2 | ก่อน: ผู้ใช้ปรับเป้าหมายหลังเวลา 05:00 น. / เมื่อ: ระบบประมวลผลเวลาการเปลี่ยนเป้าหมาย / แล้ว: เป้าหมายใหม่จะมีผลในรอบวันถัดไป (เริ่มนับ 05:00 น. ของวันถัดไป) | เป้าหมายของรอบวันปัจจุบันยังคงใช้ค่าเดิม จนกว่าจะถึงเวลา 05:00 น. ของวันถัดไป |
| AC-5 | US-3 | ก่อน: ผู้ใช้เดินได้ค่า % Goal ต่างๆ / เมื่อ: ระบบคำนวณ `(ก้าวเดินจริง / เป้าหมาย) * 100` / แล้ว: แสดงสถานะสัตว์เลี้ยงตรงตามช่วง % | <35% แสดง "อ้วนอืด" (FAT), 35%-69.99% แสดง "จ่ำม่ำ" (CHUBBY), 70%-99.99% แสดง "หุ่นลีน (สมส่วน)" (LEAN), และ >=100% แสดง "มีกล้ามขา" (MUSCLE) |
| AC-6 | US-1, US-3 | ก่อน: เวลาถึง 05:00 น. / เมื่อ: ระบบถึงเวลาตัดรอบสถิติจับเวลาประจำวัน / แล้ว: จำนวนก้าวและหลอดพลังงานถูกรีเซ็ตเป็น 0 และเริ่มรอบวันใหม่ทันที | จำนวนก้าวประจำวันเป็น 0 และ % Goal เริ่มนับใหม่ ณ เวลา 05:00:00 น. |
| AC-7 | US-4 | ก่อน: อยู่ในหน้าสรุปผลรายเดือน / เมื่อ: ผู้ใช้กดปุ่มส่งออกรายงาน (Export PNG) / แล้ว: ระบบสร้างภาพ PNG 1 หน้าถ้วนที่รวมข้อมูลก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน และจำนวนวันที่ทำเป้าหมายสำเร็จ | ไฟล์ภาพ PNG ถูกดาวน์โหลด/บันทึกเข้าเครื่องสำเร็จโดยแสดงข้อมูลครบทั้ง 4 ตัวแปรถูกต้องตรงกับฐานข้อมูล |

## 5. Edge cases
| ID | สถานการณ์ | ผลที่คาดหวัง |
|---|---|---|
| EC-1 | การปฏิเสธสิทธิ์ (Permission Denied): ผู้ใช้กดปฏิเสธสิทธิ์เข้าถึงเซนเซอร์นับก้าว | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือน และมีปุ่ม Shortcut พาผู้ใช้ไปหน้า Settings ของเครื่อง |
| EC-2 | กรณีแบตเตอรี่หมด/ปิดเครื่อง (Battery Drain / Device Shutdown): แบตเตอรี่หมดหรือเครื่องดับระหว่างวัน | ระบบดึงข้อมูลก้าวล่าสุดที่มีการบันทึกไว้ใน Local Storage มาแสดงผลโดยอัตโนมัติทันทีเมื่อเปิดแอปครั้งถัดไป |
| EC-3 | การเปลี่ยน Timezone หรือเวลาในเครื่อง (Timezone / Clock Modification): ผู้ใช้ปรับเวลาในเครื่องย้อนหลัง | ระบบยึดเวลาตาม Network/Server Time เท่านั้น ป้องกันการปรับเวลารีเซ็ตสถิติย้อนหลัง |
| EC-4 | การสลับอุปกรณ์ (Multi-device Sync): ผู้ใช้สลับไปใช้อุปกรณ์เครื่องใหม่ระหว่างวัน | ระบบ Sync เป้าหมายล่าสุดและดึงสถิติก้าวเดินสะสมเฉพาะของวันนั้นมาแสดงผลโดยไม่นับก้าวซ้ำซ้อน |
| EC-5 | การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing): เปิดหน้าจอแอปค้างไว้จนถึง 05:00 น. | ระบบทำการตัดรอบสถิติ รีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มรอบวันใหม่อัตโนมัติทันทีโดยไม่ต้อง Restart แอป |
| EC-6 | กรณีอุปกรณ์ไม่มีฮาร์ดแวร์เซนเซอร์นับก้าว (No Hardware Step Counter): อุปกรณ์ไม่มีเซนเซอร์ฮาร์ดแวร์นับก้าว | ระบบแสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และทำการล็อกฟังก์ชันนับก้าวทั้งหมด (แนวทางเดียวกับ EC-1) |

## 6. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ระบบแจ้งเตือน Push Notification เมื่อเดินใกล้ถึงเป้าหมาย (เช่น แจ้งเตือนเมื่อเดินถึง 80% หรือเหลืออีก 1,000 ก้าว)
- หน้าแดชบอร์ดสรุปสถิติและกราฟแนวโน้มแสดงผลรายสัปดาห์/รายเดือนภายในแอป (In-App Dashboard)
- ระบบแข่งขันนับก้าวกับเพื่อนหรือระบบจัดอันดับ (Leaderboard)
- การเชื่อมต่อกับ Smartwatch หรืออุปกรณ์ภายนอก (Apple Health / Google Fit / Garmin / Fitbit)

~~~~text
## 3. ขั้นตอนการใช้งาน (happy path)

1. **เปิดแอปครั้งแรก:** ผู้ใช้เปิดแอป PetPal Health ระบบแสดงหน้าขอสิทธิ์เซนเซอร์นับก้าว ผู้ใช้กด "อนุญาต" ระบบเริ่มบันทึกก้าวเดินแบบ Passive และแสดงหน้าหลัก (S-1) โดยแสดงจำนวนก้าวเป็น 0 และแสดงรูปร่างสัตว์เลี้ยงเริ่มต้นตาม % Goal
2. **การนับก้าวอัตโนมัติ:** เมื่อผู้ใช้เคลื่อนไหวร่างกาย ระบบนับก้าวเดินอัตโนมัติและอัปเดตตัวเลขก้าวเดิน หลอดพลังงาน และรูปร่างสัตว์เลี้ยงบนหน้า S-1 แบบ Real-time ตามเงื่อนไข % Goal
3. **การตั้งเป้าหมาย:** ผู้ใช้กดปุ่ม "ตั้งเป้าหมาย" ในหน้า S-1 เพื่อเข้าสู่หน้า S-2 เลือกเป้าหมายที่ต้องการ (เช่น 8,000 ก้าว) แล้วกด "บันทึก" ระบบบันทึกค่าเป้าหมายใหม่ทันทีและพาผู้ใช้กลับสู่หน้า S-1
4. **การส่งออกรายงาน:** ผู้ใช้กดปุ่ม "รายงานประจำเดือน" ในหน้า S-1 เพื่อเข้าสู่หน้า S-3 จากนั้นกดปุ่ม "ส่งออกรายงาน (PNG)" ระบบสร้างภาพ PNG รวมข้อมูล 4 ตัว변 (ก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน, วันที่สำเร็จเป้าหมาย) และบันทึกเข้าเครื่องสำเร็จ
~~~~

You are UX และ Game Designer สำหรับแอป PetPal Health. คุณเป็น UX และ Game Designer ของทีม PetPal Health มีหน้าที่แปลง requirements ของฟีเจอร์ให้เป็นประสบการณ์ใช้งานและกติกาที่ทีมพัฒนาสามารถนำไปใช้ได้จริง

* เมื่อข้อกำหนดสองข้อมีเงื่อนไขที่อาจขัดแย้งกัน ห้ามเลือกตีความข้อใดข้อหนึ่งเอง ต้องระบุรหัสข้อกำหนดทั้งสอง ข้อความหรือเงื่อนไขที่ขัดแย้ง และคำถามที่ต้องให้ Product ยืนยัน
* ห้ามเปลี่ยนข้อกำหนดที่ระบุไว้ให้กลายเป็นกติกาใหม่โดยไม่มีหลักฐานจาก Requirements
* แยกค่าที่กำหนดแล้ว ค่าที่เสนอ และค่าที่รอการยืนยันออกจากกันอย่างชัดเจน โดยเฉพาะค่าเริ่มต้น การคำนวณค่าเฉลี่ย และเงื่อนไขการเปลี่ยนเป้าหมาย
* ตรวจสอบว่า Game Rules ใช้ชื่อค่าที่มีความหมายตรงกับข้อมูลจริง เช่น ค่าเริ่มต้นต้องไม่ถูกแทนด้วยรายการตัวเลือกหลายค่า
* การรีเซ็ตข้อมูลประจำวันต้องไม่ถูกตีความว่าเป็นการลบประวัติรายเดือน เว้นแต่ Requirements ระบุไว้อย่างชัดเจน
* รายละเอียดด้านเทคนิค เช่น Server Time, การซิงก์หลายอุปกรณ์ และการป้องกันการนับซ้ำ ต้องแยกผลลัพธ์ที่กำหนดใน Requirements ออกจากวิธี implementation ที่ยังไม่ได้ตัดสินใจ
* หากยังมีข้อกำหนดที่คลุมเครือ ให้แสดงสถานะรอยืนยันจาก Product และห้ามระบุว่าเอกสารพร้อมส่งให้ Dev โดยไม่มีเงื่อนไข
Your personal goal is: แปลง requirements ของฟีเจอร์ steps ให้เป็น UX flow และ game rules ที่ชัดเจน ใช้งานง่าย มีรายละเอียดเพียงพอสำหรับ Dev นำไปพัฒนา และสามารถตรวจสอบได้โดย Reviewer

# Requirements: การนับก้าวและการตั้งเป้าหมายประจำวัน (steps)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Product agent · ผู้ตรวจ: Senior PM · อ้างอิง Issue: #101

## 1. สรุปฟีเจอร์
ฟีเจอร์บันทึกก้าวเดินประจำวันอัตโนมัติ (Passive Tracking) เพื่อตัดรอบสถิติทุก 05:00 น. นำก้าวเดินเทียบกับเป้าหมายเพื่อคำนวณ % พลังงานขับเคลื่อนรูปร่างสัตว์เลี้ยงเสมือนจริง และรองรับการส่งออกรายงานสรุปผลรายเดือนเป็นไฟล์ภาพ PNG

## 2. ตารางแสดงสถานะสัตว์เลี้ยงตามเปอร์เซ็นต์การเดิน (Pet Status Mapping)
| เปอร์เซ็นต์การเดิน (% Goal) | สถานะและรูปร่างของสัตว์เลี้ยง |
|---|---|
| < 35% | อ้วนอืด |
| 35% - 69.99% | จ่ำม่ำ |
| 70% - 99.99% | หุ่นลีน (สมส่วน) |
| 100% ขึ้นไป | มีกล้ามขา |

## 3. User stories
| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | ผู้ใช้แอป PetPal Health | ให้ระบบนับก้าวเดินของฉันโดยอัตโนมัติ | ฉันไม่ต้องคอยกดเปิดปิดการนับก้าวด้วยตนเอง |
| US-2 | ผู้ใช้ที่ต้องการดูแลสุขภาพ | สามารถตั้งค่าและปรับเปลี่ยนเป้าหมายก้าวเดินประจำวันได้ | สอดคล้องกับขีดความสามารถและเป้าหมายการออกกำลังกายของตนเอง |
| US-3 | เจ้าของสัตว์เลี้ยง | เห็นรูปร่างและสถานะของสัตว์เลี้ยงเสมือนจริงเปลี่ยนแปลงไปตาม % ก้าวเดิน | ทราบผลลัพธ์และมีแรงจูงใจในการเดินให้ครบเป้าหมาย |
| US-4 | ผู้ใช้ที่ต้องการสรุปผลสุขภาพ | สามารถส่งออกรายงานสรุปผลประจำเดือนในรูปแบบภาพ PNG ได้ | นำไปแชร์หรือเก็บไว้ดูความสำเร็จร่วมกับการดื่มน้ำ |

## 4. Acceptance criteria
| ID | อ้างถึง | เงื่อนไข (ก่อน / เมื่อ / แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | ก่อน: ผู้ใช้เปิดแอปครั้งแรก / เมื่อ: ระบบขอสิทธิ์เซนเซอร์นับก้าวและผู้ใช้กดอนุญาต / แล้ว: ระบบเริ่มบันทึกก้าวเดินแบบ Passive | บันทึกก้าวเดินเพิ่มขึ้นตามการเคลื่อนไหวจริงโดยไม่มีค่าความคลาดเคลื่อนเกิน 5% จากฮาร์ดแวร์เครื่อง |
| AC-2 | US-2 | ก่อน: อยู่ในหน้าตั้งเป้าหมาย / เมื่อ: ผู้ใช้เลือกเป้าหมายกลุ่มทั่วไป (6,000 / 7,000 / 8,000) กลุ่มควบคุมน้ำหนัก (9,000 - 12,000) หรือกลุ่มนักกีฬา (13,000 - 15,000) แล้วกดบันทึก / แล้ว: ระบบบันทึกค่าเป้าหมายใหม่ทันที | ค่าเป้าหมายใหม่ถูกอัปเดตในฐานข้อมูลและนำไปคำนวณ % Goal ทันที |
| AC-3 | US-2 | ก่อน: ผู้ใช้ปรับเปลี่ยนเป้าหมายครั้งที่ 1 สำเร็จ / เมื่อ: ผู้ใช้พยายามกดเปลี่ยนเป้าหมายอีกครั้งภายในวันเดียวกัน (ก่อน 05:00 น.) / แล้ว: ปุ่มปรับเป้าหมายถูก Disabled (สีเทาจาง) และแสดง Toast Message | แสดงข้อความ *"คุณสามารถปรับเปลี่ยนเป้าหมายได้เพียง 1 ครั้งต่อวัน"* และไม่ให้บันทึกค่าซ้ำ |
| AC-4 | US-2 | ก่อน: ผู้ใช้ปรับเป้าหมายหลังเวลา 05:00 น. / เมื่อ: ระบบประมวลผลเวลาการเปลี่ยนเป้าหมาย / แล้ว: เป้าหมายใหม่จะมีผลในรอบวันถัดไป (เริ่มนับ 05:00 น. ของวันถัดไป) | เป้าหมายของรอบวันปัจจุบันยังคงใช้ค่าเดิม จนกว่าจะถึงเวลา 05:00 น. ของวันถัดไป |
| AC-5 | US-3 | ก่อน: ผู้ใช้เดินได้ค่า % Goal ต่างๆ / เมื่อ: ระบบคำนวณ `(ก้าวเดินจริง / เป้าหมาย) * 100` / แล้ว: แสดงสถานะสัตว์เลี้ยงตรงตามช่วง % | <35% แสดง "อ้วนอืด" (FAT), 35%-69.99% แสดง "จ่ำม่ำ" (CHUBBY), 70%-99.99% แสดง "หุ่นลีน (สมส่วน)" (LEAN), และ >=100% แสดง "มีกล้ามขา" (MUSCLE) |
| AC-6 | US-1, US-3 | ก่อน: เวลาถึง 05:00 น. / เมื่อ: ระบบถึงเวลาตัดรอบสถิติจับเวลาประจำวัน / แล้ว: จำนวนก้าวและหลอดพลังงานถูกรีเซ็ตเป็น 0 และเริ่มรอบวันใหม่ทันที | จำนวนก้าวประจำวันเป็น 0 และ % Goal เริ่มนับใหม่ ณ เวลา 05:00:00 น. |
| AC-7 | US-4 | ก่อน: อยู่ในหน้าสรุปผลรายเดือน / เมื่อ: ผู้ใช้กดปุ่มส่งออกรายงาน (Export PNG) / แล้ว: ระบบสร้างภาพ PNG 1 หน้าถ้วนที่รวมข้อมูลก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน และจำนวนวันที่ทำเป้าหมายสำเร็จ | ไฟล์ภาพ PNG ถูกดาวน์โหลด/บันทึกเข้าเครื่องสำเร็จโดยแสดงข้อมูลครบทั้ง 4 ตัวแปรถูกต้องตรงกับฐานข้อมูล |

## 5. Edge cases
| ID | สถานการณ์ | ผลที่คาดหวัง |
|---|---|---|
| EC-1 | การปฏิเสธสิทธิ์ (Permission Denied): ผู้ใช้กดปฏิเสธสิทธิ์เข้าถึงเซนเซอร์นับก้าว | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือน และมีปุ่ม Shortcut พาผู้ใช้ไปหน้า Settings ของเครื่อง |
| EC-2 | กรณีแบตเตอรี่หมด/ปิดเครื่อง (Battery Drain / Device Shutdown): แบตเตอรี่หมดหรือเครื่องดับระหว่างวัน | ระบบดึงข้อมูลก้าวล่าสุดที่มีการบันทึกไว้ใน Local Storage มาแสดงผลโดยอัตโนมัติทันทีเมื่อเปิดแอปครั้งถัดไป |
| EC-3 | การเปลี่ยน Timezone หรือเวลาในเครื่อง (Timezone / Clock Modification): ผู้ใช้ปรับเวลาในเครื่องย้อนหลัง | ระบบยึดเวลาตาม Network/Server Time เท่านั้น ป้องกันการปรับเวลารีเซ็ตสถิติย้อนหลัง |
| EC-4 | การสลับอุปกรณ์ (Multi-device Sync): ผู้ใช้สลับไปใช้อุปกรณ์เครื่องใหม่ระหว่างวัน | ระบบ Sync เป้าหมายล่าสุดและดึงสถิติก้าวเดินสะสมเฉพาะของวันนั้นมาแสดงผลโดยไม่นับก้าวซ้ำซ้อน |
| EC-5 | การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing): เปิดหน้าจอแอปค้างไว้จนถึง 05:00 น. | ระบบทำการตัดรอบสถิติ รีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มรอบวันใหม่อัตโนมัติทันทีโดยไม่ต้อง Restart แอป |
| EC-6 | กรณีอุปกรณ์ไม่มีฮาร์ดแวร์เซนเซอร์นับก้าว (No Hardware Step Counter): อุปกรณ์ไม่มีเซนเซอร์ฮาร์ดแวร์นับก้าว | ระบบแสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และทำการล็อกฟังก์ชันนับก้าวทั้งหมด (แนวทางเดียวกับ EC-1) |

## 6. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ระบบแจ้งเตือน Push Notification เมื่อเดินใกล้ถึงเป้าหมาย (เช่น แจ้งเตือนเมื่อเดินถึง 80% หรือเหลืออีก 1,000 ก้าว)
- หน้าแดชบอร์ดสรุปสถิติและกราฟแนวโน้มแสดงผลรายสัปดาห์/รายเดือนภายในแอป (In-App Dashboard)
- ระบบแข่งขันนับก้าวกับเพื่อนหรือระบบจัดอันดับ (Leaderboard)
- การเชื่อมต่อกับ Smartwatch หรืออุปกรณ์ภายนอก (Apple Health / Google Fit / Garmin / Fitbit)

## 3. ขั้นตอนการใช้งาน (happy path)

1. **เปิดแอปครั้งแรก:** ผู้ใช้เปิดแอป PetPal Health ระบบแสดงหน้าขอสิทธิ์เซนเซอร์นับก้าว ผู้ใช้กด "อนุญาต" ระบบเริ่มบันทึกก้าวเดินแบบ Passive และแสดงหน้าหลัก (S-1) โดยแสดงจำนวนก้าวเป็น 0 และแสดงรูปร่างสัตว์เลี้ยงเริ่มต้นตาม % Goal
2. **การนับก้าวอัตโนมัติ:** เมื่อผู้ใช้เคลื่อนไหวร่างกาย ระบบนับก้าวเดินอัตโนมัติและอัปเดตตัวเลขก้าวเดิน หลอดพลังงาน และรูปร่างสัตว์เลี้ยงบนหน้า S-1 แบบ Real-time ตามเงื่อนไข % Goal
3. **การตั้งเป้าหมาย:** ผู้ใช้กดปุ่ม "ตั้งเป้าหมาย" ในหน้า S-1 เพื่อเข้าสู่หน้า S-2 เลือกเป้าหมายที่ต้องการ (เช่น 8,000 ก้าว) แล้วกด "บันทึก" ระบบบันทึกค่าเป้าหมายใหม่ทันทีและพาผู้ใช้กลับสู่หน้า S-1
4. **การส่งออกรายงาน:** ผู้ใช้กดปุ่ม "รายงานประจำเดือน" ในหน้า S-1 เพื่อเข้าสู่หน้า S-3 จากนั้นกดปุ่ม "ส่งออกรายงาน (PNG)" ระบบสร้างภาพ PNG รวมข้อมูล 4 ตัว변 (ก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน, วันที่สำเร็จเป้าหมาย) และบันทึกเข้าเครื่องสำเร็จ

~~~~text
| กรณี | ผลลัพธ์ที่ทดสอบได้ |
|---|---|
| ค่าเกินขอบบน (% Goal สูงกว่า 100%) | สัตว์เลี้ยงยังคงแสดงสถานะ "มีกล้ามขา" (MUSCLE) และคำนวณค่า % Goal ตามจริง (เช่น 120%) โดยไม่มีการจำกัดเพดานตัวเลขเปอร์เซ็นต์ แต่ใช้ภาพสัตว์เลี้ยงชุดเดียวกับเกณฑ์ >= 100% |
| ค่าต่ำกว่าขอบล่าง (จำนวนก้าวติดลบหรือ 0) | ระบบแสดงจำนวนก้าวเป็น 0 และ % Goal เป็น 0% พร้อมแสดงสถานะ "อ้วนอืด" (FAT) |
| การเปลี่ยนเป้าหมายซ้ำในวันเดียวกัน (ก่อน 05:00 น.) | ปุ่มบันทึกเป้าหมายถูกเปลี่ยนเป็นสถานะ Disabled (สีเทาจาง) และแสดง Toast Message: *"คุณสามารถปรับเปลี่ยนเป้าหมายได้เพียง 1 ครั้งต่อวัน"* ทันทีเมื่อผู้ใช้พยายามกด |
| การเปลี่ยนเป้าหมายหลังเวลา 05:00 น. | ค่าเป้าหมายใหม่จะถูกบันทึกไว้ในฐานข้อมูล แต่จะยังไม่มีผลกับรอบวันปัจจุบัน โดยรอบวันปัจจุบันยังคงใช้เป้าหมายเดิมจนกระทั่งถึงเวลา 05:00:00 น. ของวันถัดไปจึงจะเริ่มใช้เป้าหมายใหม่ |
| การปฏิเสธสิทธิ์เซนเซอร์นับก้าว (EC-1) และไม่มีฮาร์ดแวร์ (EC-6) | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และแสดงปุ่ม Shortcut พาผู้ใช้ไปหน้า Settings ของเครื่อง |
| แบตเตอรี่หมดหรือเครื่องดับระหว่างวัน (EC-2) | ระบบดึงข้อมูลก้าวล่าสุดที่มีการบันทึกสำรองไว้ใน Local Storage มาแสดงผลโดยอัตโนมัติทันทีเมื่อเปิดแอปพลิเคชันครั้งถัดไป |
| การปรับเวลาในเครื่องย้อนหลัง (EC-3) | ระบบบังคับใช้เวลาอ้างอิงตาม Network/Server Time เท่านั้น เพื่อป้องกันการปรับเวลารีเซ็ตสถิติย้อนหลัง |
| การสลับอุปกรณ์ระหว่างวัน (EC-4) | ระบบทำการ Sync เป้าหมายล่าสุดและดึงสถิติก้าวเดินสะสมเฉพาะของวันนั้นมาจาก Server โดยไม่นับก้าวซ้ำซ้อน |
| การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing / EC-5) | ระบบดำเนินการตัดรอบสถิติ ทำการรีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มรอบวันใหม่อัตโนมัติทันทีบนหน้าจอโดยผู้ใช้ไม่ต้องทำการ Restart แอปพลิเคชัน |

## 5. คำถามถึง Product

1. ค่าเริ่มต้นของเป้าหมายประจำวัน (`DEFAULT_DAILY_GOAL`) สำหรับผู้ใช้ใหม่ที่เปิดแอปครั้งแรก กำหนดไว้ที่จำนวนก้าวเท่าใด ขอความยืนยันจาก Product เนื่องจากในเอกสาร Requirements ยังไม่ได้ระบุตัวเลขที่แน่ชัด
2. รูปแบบการเลือกเป้าหมายในกลุ่มควบคุมน้ำหนัก (9,000 - 12,000 ก้าว) และกลุ่มนักกีฬา (13,000 - 15,000 ก้าว) ในหน้าตั้งเป้าหมาย (S-2) ต้องการให้ผู้ใช้เลือกตัวเลขแบบใด (เช่น เป็นตัวเลือกค่ามาตรฐานที่กำหนดไว้ล่วงหน้า หรือให้ผู้ใช้พิมพ์ระบุตัวเลขเองแบบอิสระภายในช่วงดังกล่าว) ขอความยืนยันจาก Product เพื่อให้ Dev พัฒนาช่องกรอกข้อมูลได้ถูกต้องตามความต้องการ
3. กรณีที่ผู้ใช้กดปุ่มส่งออกรายงาน (Export PNG) ในหน้า S-3 แล้วเกิดข้อผิดพลาดในการบันทึกไฟล์ลงเครื่อง (เช่น หน่วยความจำอุปกรณ์เต็มหรือไม่มีพื้นที่จัดเก็บเพียงพอ) ระบบต้องการให้แสดง Pop-up แจ้งเตือนด้วยข้อความใด ขอความยืนยันเพิ่มเติมเนื่องจาก Requirements ยังไม่ได้กำหนดพฤติกรรมในกรณีนี้
~~~~

~~~~text
## 3. ขั้นตอนการใช้งาน (happy path)

1. **เปิดแอปครั้งแรก:** ผู้ใช้เปิดแอป PetPal Health ระบบแสดงหน้าขอสิทธิ์เซนเซอร์นับก้าว ผู้ใช้กด "อนุญาต" ระบบเริ่มบันทึกก้าวเดินแบบ Passive และแสดงหน้าหลัก (S-1) โดยแสดงจำนวนก้าวเป็น 0 และแสดงรูปร่างสัตว์เลี้ยงเริ่มต้นตาม % Goal
2. **การนับก้าวอัตโนมัติ:** เมื่อผู้ใช้เคลื่อนไหวร่างกาย ระบบนับก้าวเดินอัตโนมัติและอัปเดตตัวเลขก้าวเดิน หลอดพลังงาน และรูปร่างสัตว์เลี้ยงบนหน้า S-1 แบบ Real-time ตามเงื่อนไข % Goal
3. **การตั้งเป้าหมาย:** ผู้ใช้กดปุ่ม "ตั้งเป้าหมาย" ในหน้า S-1 เพื่อเข้าสู่หน้า S-2 เลือกเป้าหมายที่ต้องการ (เช่น 8,000 ก้าว) แล้วกด "บันทึก" ระบบบันทึกค่าเป้าหมายใหม่ทันทีและพาผู้ใช้กลับสู่หน้า S-1
4. **การส่งออกรายงาน:** ผู้ใช้กดปุ่ม "รายงานประจำเดือน" ในหน้า S-1 เพื่อเข้าสู่หน้า S-3 จากนั้นกดปุ่ม "ส่งออกรายงาน (PNG)" ระบบสร้างภาพ PNG รวมข้อมูล 4 ตัว변 (ก้าวเดินรวม, น้ำดื่มรวม, ค่าเฉลี่ยรายวัน, วันที่สำเร็จเป้าหมาย) และบันทึกเข้าเครื่องสำเร็จ
~~~~

~~~~text
## 4. พฤติกรรมที่ขอบเขต

| กรณี | ผลลัพธ์ที่ทดสอบได้ |
|---|---|
| ค่าเกินขอบบน (% Goal สูงกว่า 100%) | สัตว์เลี้ยงยังคงแสดงสถานะ "มีกล้ามขา" (MUSCLE) และคำนวณค่า % Goal ตามจริง (เช่น 120%) โดยไม่มีการจำกัดเพดานตัวเลขเปอร์เซ็นต์ แต่ใช้ภาพสัตว์เลี้ยงชุดเดียวกับเกณฑ์ >= 100% |

| การเปลี่ยนเป้าหมายหลังเวลา 05:00 น. | ค่าเป้าหมายใหม่จะถูกบันทึกไว้ในฐานข้อมูล แต่จะยังไม่มีผลกับรอบวันปัจจุบัน โดยรอบวันปัจจุบันยังคงใช้เป้าหมายเดิมจนกระทั่งถึงเวลา 05:00:00 น. ของวันถัดไปจึงจะเริ่มใช้เป้าหมายใหม่ |
| การปฏิเสธสิทธิ์เซนเซอร์นับก้าว (EC-1) และไม่มีฮาร์ดแวร์ (EC-6) | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือนข้อจำกัดของอุปกรณ์ และแสดงปุ่ม Shortcut พาผู้ใช้ไปหน้า Settings ของเครื่อง |

## 5. คำถามถึง Product

1. ค่าเริ่มต้นของเป้าหมายประจำวัน (`DEFAULT_DAILY_GOAL`) สำหรับผู้ใช้ใหม่ที่เปิดแอปครั้งแรก กำหนดไว้ที่จำนวนก้าวเท่าใด ขอความยืนยันจาก Product เนื่องจากในเอกสาร Requirements ยังไม่ได้ระบุตัวเลขที่แน่ชัด
2. รูปแบบการเลือกเป้าหมายในกลุ่มควบคุมน้ำหนัก (9,000 - 12,000 ก้าว) และกลุ่มนักกีฬา (13,000 - 15,000 ก้าว) ในหน้าตั้งเป้าหมาย (S-2) ต้องการให้ผู้ใช้เลือกตัวเลขแบบใด (เช่น เป็นตัวเลือกค่ามาตรฐานที่กำหนดไว้ล่วงหน้า หรือให้ผู้ใช้พิมพ์ระบุตัวเลขเองแบบอิสระภายในช่วงดังกล่าว) ขอความยืนยันจาก Product เพื่อให้ Dev พัฒนาช่องกรอกข้อมูลได้ถูกต้องตามความต้องการ
3. กรณีที่ผู้ใช้กดปุ่มส่งออกรายงาน (Export PNG) ในหน้า S-3 แล้วเกิดข้อผิดพลาดในการบันทึกไฟล์ลงเครื่อง (เช่น หน่วยความจำอุปกรณ์เต็มหรือไม่มีพื้นที่จัดเก็บเพียงพอ) ระบบต้องการให้แสดง Pop-up แจ้งเตือนด้วยข้อความใด ขอความยืนยันเพิ่มเติมเนื่องจาก Requirements ยังไม่ได้กำหนดพฤติกรรมในกรณีนี้
~~~~
