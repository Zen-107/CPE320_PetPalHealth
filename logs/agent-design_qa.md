# Agent design log — qa

ไฟล์: `agents/qa.md` (CrewAI) + `.claude/agents/qa.md` (Claude Code sub-agent)

## v0 — แม่แบบตั้งต้น (commit 4321f9b)

- **role:** QA Engineer ของแอป PetPal Health
- **goal:** พิสูจน์ด้วยเทสต์ว่าฟีเจอร์ {feature} ทำงานตรง acceptance criteria และกติกาเกมทุกข้อ รวมถึง edge cases
- **backstory (สรุป):** ทำตาราง AC → ชื่อเทสต์ · ทดสอบ **ทุกขอบของทุกช่วง** (ขอบพอดี, ขอบ−1, ขอบ+1), max/min, ข้ามวัน · ใช้เวลาที่ควบคุมได้ ห้าม sleep · unit test + widget test · ตัวเลขคาดหวังมาจากเอกสาร · **ห้ามแก้ app/lib/** · รายงานในคำตอบ: ผ่าน/ไม่ผ่าน, AC ที่ยังไม่มีเทสต์, bug
- **tools:** Read, Grep, Glob, Edit, Write, Bash
- **ปัญหาของ v0**
  - `.claude/agents/qa.md` ไม่มี role/goal/backstory ในไฟล์
  - ไม่มี owner / input_files / output_file
  - "ทุกขอบของทุกช่วง" ทำให้มีเทสต์มากเกินจำเป็น
  - เมื่อเทสต์พังไม่ได้แยกว่าเทสต์ผิดหรือโค้ดผิด
  - รายงานอยู่แค่ในแชต ไม่มีไฟล์และไม่มีตัวเลขให้ C ทำ metrics

## v1 — 2026-10-08

| ประเด็น | ตัดสินใจ | เหตุผล |
|---|---|---|
| ความครอบคลุม | ทุก AC ต้องมีเทสต์อย่างน้อย 1 เทสต์ · edge case เฉพาะที่เสี่ยง | AC คือสัญญากับเอกสาร จึงต้องครบ · edge case แบบครอบทุกขอบทำให้เทสต์บวมและเสียเวลา จึงเลือกเฉพาะจุดที่น่าจะพังจริง |
| edge case ที่ "เสี่ยง" (ต้องมีเสมอ) | ค่าเกณฑ์พอดี (พอดี และเกิน 1 หน่วย) · เวลาข้ามวัน/รีเซ็ต/streak · ค่าติดเพดาน max/min · ข้อมูลว่างหรือเปิดแอปครั้งแรกหรือข้อมูลเสีย | 4 จุดนี้เป็นจุดที่แอปลักษณะนี้พังบ่อยที่สุด และเป็นจุดที่อารมณ์สัตว์เปลี่ยน ซึ่งผู้ใช้เห็นทันที |
| เทสต์ไม่ผ่าน | แยกก่อนโดยเทียบกับเอกสาร: ถ้าเทสต์ผิดให้แก้เทสต์เองและจดไว้ · ถ้าโค้ดผิดให้รายงาน bug ให้ Dev (ยังห้ามแก้ app/lib/) · ถ้าเอกสารไม่ชัดหรือเป็นค่าชั่วคราวของ Dev ให้จดเป็นคำถาม ไม่นับเป็น bug | ไม่โยน false bug ให้ Dev และสอดคล้องกับกฎของ Dev ที่ใส่ `// ASSUMPTION` ไว้ |
| อ่าน log ของ Dev | อ่าน `logs/*_dev_<feature>.md` ก่อนเขียนเทสต์ | จะได้รู้ว่าค่าไหนเป็นค่าชั่วคราวหรือสมมติฐาน |
| รายงาน | `docs/<feature>/test-report.md`: ตาราง AC \| ชื่อเทสต์ \| ผ่าน/ไม่ผ่าน + สรุปตัวเลข + bug (ขั้นตอนทำซ้ำ, ผลที่คาด, ผลจริง) + คำถาม | เก็บผลไว้คู่กับเอกสารฟีเจอร์ C และอาจารย์เปิดดูได้ที่เดียว |
| ตัวเลขการทำงาน | `logs/<YYYYMMDD-HHMM>_qa_<feature>.md`: จำนวนรอบที่รันเทสต์, เวลาที่ใช้, bug ที่เจอ/ที่แก้แล้ว, จำนวนเทสต์ที่แก้เองเพราะเทสต์ผิด · ห้ามแต่งตัวเลข | ให้ C ใช้ทำ metrics ตามเกณฑ์ข้อ 11 (ตัวเลขต้องตรงกับ logs/) |
