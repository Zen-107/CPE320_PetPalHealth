# Brief: 7-Day Health History & Weekly Summary Feature (7day)

## Overview
ฟีเจอร์ประวัติ 7 วัน (`7day`) ของแอป PetPal Health ทำหน้าที่แสดงผลสถิติกิจกรรมสุขภาพย้อนหลัง (การกิน `food`, การเดิน `steps`, การดื่มน้ำ `water`) เพื่อให้ผู้ใช้เห็นแนวโน้มพฤติกรรมสุขภาพของตนเอง โดยเน้นการแสดงผลข้อมูลตัวเลขที่กระชับ การ์ดสรุปภาพรวมด้านบน และ Card สรุปรายวัน 7 วันแบบ Minimal พับเก็บได้ โดยไม่มีการแสดงผลตัวละครสัตว์เลี้ยงในหน้านี้

## 1. Date Window, Normalizer & Reset Rules (ขอบเขตเวลาและการดึงข้อมูล)
- **7-Day Window:** นับจาก **วันปัจจุบัน (Current Day) อยู่บนสุด + ย้อนหลัง 6 วันก่อนหน้า** (รวมเป็น 7 วันพอดี)
- **Date Normalizer Rule:** การดึงข้อมูล 7 วัน **ต้องผ่านฟังก์ชันแปลงวันที่ (Date Normalizer) ที่อิงตามวันปฏิทินของรอบ 05:00 น. (ICT / UTC+7) เสมอ** ก่อนนำมาคำนวณและ Query ข้อมูล เพื่อป้องกันปัญหา Timezone หรือข้อมูลข้ามวันผิดพลาด
- **Cut-off Time:** อ้างอิง Server Time ตัดรอบวันใหม่เวลา 05:00 น. (ICT) เช่นเดียวกับหน้า Dashboard

## 2. Weekly Summary Card & Inconsistent Data Handling (การ์ดสรุปภาพรวมด้านบน)
การ์ดส่วนบนสุดแสดงค่าเฉลี่ยของทั้ง 3 กิจกรรม โดยมีเงื่อนไขการคำนวณและการแสดงข้อความดังนี้:
- **Calculation Formula:** 
  $$\text{Average} = \frac{\sum(\text{Values})}{\text{Count}(\text{Days with Records})}$$
  *(คำนวณค่าเฉลี่ยเฉพาะวันที่มีการบันทึกข้อมูลจริงเท่านั้น ไม่นำวันที่ไม่มีข้อมูลมาร่วมหาร)*
- **Number Format:** ค่าเฉลี่ยแสดงผลเป็น **ทศนิยม 1 ตำแหน่ง** เสมอ (เช่น 6.5 แก้ว, 7,240.5 ก้าว)
- **Inconsistent Logging Notice & Rule-based Coaching Text:**
  - หากใน 7 วันมีวันที่ไม่มีข้อมูลปะปนอยู่ (Count < 7 วัน) การ์ดสรุปด้านบนจะต้องแสดงข้อความนำหน้า:
    `"มีการบันทึกไม่สม่ำเสมอ จากข้อมูลการบันทึกเท่าที่มีพบว่า..."`
  - ตามด้วยข้อความแนะนำ Rule-based ตามเงื่อนไขดังนี้:
    - *กรณีน้ำดื่มเฉลี่ย < 8 แก้ว:* `"ดื่มน้ำเฉลี่ยวันละ {val} แก้ว น้อยไปน้า พยายามกินน้ำมากกว่านี้ แต่เก่งมากแล้วดูแลสุขภาพต่อไปนะ"`
    - *กรณีการเดินเฉลี่ย < 8,000 ก้าว:* `"เดินเฉลี่ยวันละ {val} ก้าว ขยับอีกนิดน้าเพื่อสุขภาพที่แข็งแรง แต่เก่งมากแล้วดูแลสุขภาพต่อไปนะ"`
    - *กรณีไม่มีข้อมูลเลยสักวันในรอบ 7 วัน:* แสดงข้อความสถานะว่า `"ยังไม่มีข้อมูลการบันทึกในรอบ 7 วันนี้"`

## 3. Daily Log Cards & Minimal Collapsible Layout (การ์ดรายวัน 7 วันด้านล่าง)
ส่วนล่างแสดงรายการ Card เรียงลำดับจาก **วันปัจจุบัน (Today) อยู่บนสุด ไล่ย้อนหลังไป 6 วัน** โดยออกแบบสำหรับ Designer (C) และ Developer (B) ดังนี้:
- **Layout Style:** แสดงแบบ **Minimal** สรุปตัวเลขสั้นๆ **ไม่มีกราฟ** และเป็นแบบ **Collapsible (พับเก็บได้)** 
- **Default Expansion Rule:** เมื่อเปิดเข้ามาหน้าประวัติ 7 วัน **ให้ Card ของ "วันปัจจุบัน" ถูกเปิดแสดงรายละเอียดไว้ (Expanded) ส่วนอีก 6 วันที่เหลือให้พับเก็บไว้ (Collapsed)** เพื่อความสะอาดตา และกดคลิกเพื่อสลับขยาย/พับได้
- **Card Contents:** ในแต่ละวันแสดงยอดการเดิน (`steps`), ยอดการดื่มน้ำ (`water`), แคลอรีอาหาร (`food`), และป้ายเตือนพิเศษหากพบ (เช่น **โซเดียมสูง / น้ำตาลสูง / Overeating**)
- **Missing Data Handling:** หากในวันนั้นผู้ใช้ไม่มีข้อมูลการบันทึกเลย การ์ดของวันนั้นในส่วนย่อยจะแสดงข้อความว่า `"ไม่มีข้อมูล"` และไม่นำไปนับเป็นตัวหาร
- **Color Highlighting:** 
  - 🟢 **สีเขียว (Pass):** บรรลุเป้าหมาย (≥ 80%)
  - 🟠 **สีส้ม (Warning):** ต่ำกว่าเป้าหมาย (50% – 79%)
  - 🔴 **สีแดง (Alert):** ต่ำกว่าเกณฑ์มาก (< 50%) หรือเกิด Overeating

## 4. Edge Cases Requirement (ครบถ้วน 5 ข้อสมบูรณ์)
ครอบคลุม Edge Cases สำคัญ 5 ข้อ:
1. **New / Inconsistent Users:** ผู้ใช้ที่มีข้อมูลไม่ครบ 7 วัน คำนวณค่าเฉลี่ยหารเฉพาะจำนวนวันที่มีการบันทึกจริงพร้อมแสดงป้ายเตือนบันทึกไม่สม่ำเสมอ
2. **Missing Data Days:** วันที่ไม่มีข้อมูลบันทึกเลย การ์ดรายวันจะแสดงสถานะ "ไม่มีข้อมูล" และไม่นำไปคำนวณรวมในยอด sum ค่าเฉลี่ย
3. **Completely Empty History:** กรณีไม่มีข้อมูลเลยตลอด 7 วัน หน้าจอจะแสดงสถานะหน้าว่าง แจ้งว่า "ยังไม่มีข้อมูลการบันทึกในรอบ 7 วันนี้"
4. **Date Transition at 05:00 ICT:** ผู้ใช้เปิดหน้าจอค้างไว้ข้ามเวลา 05:00 น. ระบบต้องทำการ Normalize วันใหม่, รีเฟรช Card รายวัน และสลับเปิด Card วันปัจจุบันอันใหม่ทันที
5. **Offline Cache:** กรณีไม่มีสัญญาณอินเทอร์เน็ต ดึงข้อมูลประวัติ 7 วันจาก Local Cache มาแสดงผลในรูปแบบ Collapsible Card ได้ปกติ
