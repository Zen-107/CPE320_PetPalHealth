# Brief: Pet Feeding & Nutrition Feature (food)

## Overview
ฟีเจอร์บันทึกการให้อาหารสัตว์เลี้ยงในแอปพลิเคชัน PetPal Health ช่วยให้ผู้ใช้บันทึกเมนูอาหารในแต่ละวัน ระบบจะทำการดึงข้อมูลพลังงาน (Calories), โซเดียม และน้ำตาลโดยอัตโนมัติผ่าน AI พร้อมทั้งคำนวณเป้าหมายแคลอรี่ประจำวันตามข้อมูลสุขภาพของผู้ใช้ เพื่อขับเคลื่อนระบบหลอดพลังงานและ Animation ท่าทางของสัตว์เลี้ยง พร้อมรองรับโครงสร้างฐานข้อมูลสำหรับสรุปประวัติย้อนหลัง 7 วัน

## 1. Calorie Goal Calculation & Reset Rules (สำหรับ Dev - ฝั่ง B)
- **Reset Time & Timezone:** ตัดรอบรีเซ็ตแคลอรี่และพลังงานประจำวัน ณ เวลา **05:00 น. อ้างอิงตามเวลาประเทศไทย (ICT / UTC+7)**
  - *Database Date Logic:* การบันทึก Log ลงฐานข้อมูล (`date`) หากผู้ใช้ทานอาหารในช่วงเวลาก่อนตี 5 ของวันใหม่ (เช่น ตี 3 ของวันที่ 15) ระบบจะต้องบันทึก Log นั้นให้อยู่ในรอบวันที่ 14 เพื่อให้สอดคล้องกับรอบโควต้าพลังงานที่ยังไม่ถูกรีเซ็ต
- **Age Input Rule:** ข้อมูลอายุผู้ใช้บังคับเป็น **จำนวนเต็มเท่านั้น (Integer) ห้ามกรอกทศนิยม** (1 - 120 ปี)
- **Base Target Table (ตารางเป้าหมายแคลอรี่พื้นฐานตามช่วงอายุและเพศแบบชัดเจน):**
  
| ช่วงอายุ (ปี) | เพศชาย (Male Base Target) | เพศหญิง (Female Base Target) |
| :--- | :--- | :--- |
| **10 – 12 ปี** | 1,700 kcal | 1,600 kcal |
| **13 – 15 ปี (Growth Spurt)** | 2,100 kcal | 1,800 kcal |
| **16 – 18 ปี** | 2,300 kcal | 1,850 kcal |
| **19 – 50 ปี (ผู้ใหญ่)** | 2,000 kcal | 1,600 kcal |
| **51 ปีขึ้นไป** | 1,800 kcal | 1,400 kcal |

- **BMI Adjustment Rules:**
  - **BMI < 18.5 (ผอม):** เพิ่มเป้าหมาย +400 kcal
  - **BMI 18.5 – 22.9 (ปกติ):** ไม่ปรับเปลี่ยน (+0 kcal)
  - **BMI ≥ 23.0 (อ้วน/น้ำหนักเกิน):** ลดเป้าหมายลง -400 kcal
- **Non-Profile Users (UI Layout สำหรับ Designer - ฝั่ง C):** 
  - หากผู้ใช้กดข้ามการกรอกโปรไฟล์ ระบบจะไม่แสดงหลอดพลังงาน % แต่จะแทนที่พื้นที่นั้นด้วย **Call-to-Action Banner** ที่มีขนาดความกว้างและสูง (Dimension) เทียบเท่ากับ Widget หลอดพลังงานเดิม เพื่อป้องกัน Layout Shift พร้อมแสดงยอดรวมแคลอรี่รายวันควบคู่กัน

## 2. Food Input & AI Parsing Mechanics (สำหรับ Dev - ฝั่ง B)
- **AI Response Format:** ระบบค้นหาอาหารจะส่งคำสั่งขอข้อมูลให้ออกมาเป็น **JSON Format** เท่านั้น เช่น `{"calories": 400, "high_sodium": true, "high_sugar": false}`
- **Range Handling:** หาก AI คืนค่าแคลอรี่เป็นช่วงตัวเลข ให้โปรแกรมนำ **ค่ากลาง (Median)** มาใช้โดยอัตโนมัติ
- **Parsing Fallback & Manual Input:** หาก AI คืนข้อความผิดรูปแบบ Parsing ตัวเลขไม่ได้ หรือค้นหาไม่พบ / อินเทอร์เน็ตหลุด ระบบจะแสดงช่องกรอกแคลอรี่เอง หากผู้ใช้ปล่อยว่างไว้จะใช้ค่า **Default ที่ 300 kcal**

## 3. Pet Animations, Toast Notifications & Threshold Rules (สำหรับ Dev & Designer - ฝั่ง B & C)
- **Pet Animation States (มี 4 ท่าทางชัดเจน):**
  1. **ท่าหิว (Hungry State):** ท่าทางปกติเมื่อแคลอรี่ยังไม่เกินเป้าหมาย
  2. **ท่ากำลังกิน (Eating State):** ท่าทางแสดงการกินอาหาร แสดงขณะกดส่งเมนูอาหารสำเร็จ
  3. **ท่าอิ่มพุงกาง (Full State):** แสดงเมื่อกินเกินเป้าหมาย **มากกว่า 100 kcal ขึ้นไป** พร้อมข้อความขึ้นว่า *"อิ่มแล้ว"*
  4. **ท่าอิ่มพุงกางแต่ยังกิน (Overeating State):** แสดงเมื่อมีการกดปุ่มบันทึกอาหารเพิ่มในขณะที่สถานะรวมเกิน > 100 kcal ไปแล้ว พร้อมข้อความเตือนว่า *"พอเถอะน้าคนดี"* (ข้อความนี้และ Animation นี้จะถูก Trigger ซ้ำทุกครั้งที่มีการกดบันทึกเพิ่มในสถานะเกินเป้าหมาย)
- **Calorie Threshold Rule (เงื่อนไขส่วนเกิน 100 kcal):** 
  - หากแคลอรี่รวมเกินเป้าหมาย แต่ **เกินมาไม่เกิน 100 kcal** ให้หลอดพลังงานยังคงแสดงผลสีปกติ (ไม่เปลี่ยนเป็นสีแดง) และสัตว์เลี้ยงยังคงอยู่ในท่าปกติ ไม่แสดงท่าอิ่มเกิน
- **Toast Message Warning & Positioning (สำหรับ Designer - ฝั่ง C & Dev - ฝั่ง B):**
  - แสดงเป็น Toast Message ลอยขึ้น **ด้านบนตัวสัตว์เลี้ยง** โดยยึดจุดอ้างอิง (Anchor point) ห่างจากขอบบนสุดของ Asset สัตว์เลี้ยง 12px เสมอ
  - จำกัดการแสดงผล **ทีละ 1 ข้อความต่อ 1 การบันทึก** (ค้าง 5 วินาที หรือ Queue replace ทันทีเมื่อส่งซ้อน)

## 4. Data Persistence & 7-Day History Support Schema (สำหรับ Dev - ฝั่ง B)
- ทุกครั้งที่มีการบันทึกหรือรีเซ็ตแคลอรี่ ระบบต้องบันทึกข้อมูลลงฐานข้อมูล (Database Schema) เพื่อรองรับฟีเจอร์สรุปประวัติย้อนหลัง 7 วัน:
  - `user_id` (String / UUID)
  - `date` (Date: YYYY-MM-DD - อ้างอิงตามรอบตัดวัน 05:00 น.)
  - `total_calories` (Integer: ยอดรวมแคลอรี่ประจำวัน)
  - `is_over_target` (Boolean: สถานะเกินเป้าหมายหรือไม่)

## 5. Edge Cases
- **EC-1 (AI Parsing Failure / Offline):** แปลงค่าแคลอรี่ไม่สำเร็จหรือเน็ตหลุด -> ระบบเปลี่ยนเป็น Form ให้กรอกแคลเอง (Default 300 kcal หากไม่กรอก)
- **EC-2 (Rapid Sequential Logging):** บันทึกเมนูใหม่ซ้อนกันภายใน 5 วิ -> Toast ข้อความเตือนเด้งสลับแสดงของเมนูใหม่ทันที (Queue Replace)
- **EC-3 (Overeating Threshold Trigger):** แคลรวมเกินเป้าหมาย **> 100 kcal** -> เปลี่ยนท่าสัตว์เลี้ยงเป็น "ท่าอิ่มพุงกาง" (หลอดสีแดง) และหากกดบันทึกเพิ่มจะแสดง "ท่าอิ่มพุงกางแต่ยังกิน" พร้อม Toast "พอเถอะน้าคนดี" ทุกครั้งที่กด (หากเกิน <= 100 kcal หลอดไม่เปลี่ยนสีและไม่ขึ้นท่าอิ่มเกิน)
- **EC-4 (Skipped Profile Layout):** ผู้ใช้ข้ามโปรไฟล์ -> แสดง CTA Banner ขนาดเท่า Widget เดิม ชวนกรอกโปรไฟล์แทนช่องหลอด % พลังงาน ป้องกัน Layout Shift
- **EC-5 (Invalid Age Input):** ผู้ใช้พยายามกรอกอายุเป็นทศนิยม -> ระบบบล็อกและบังคับให้กรอกเป็นจำนวนเต็ม (Integer 1-120) เท่านั้น

## 6. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- การสแกนรูปภาพอาหารด้วย AI (Food Image Recognition / Camera Scan)
- การแยกสัดส่วนสารอาหารเชิงลึก (Carb / Protein / Fat breakdown)
- การตั้งค่าแจ้งเตือนเวลาทานอาหารอัตโนมัติ (Meal Reminder Push Notification)
