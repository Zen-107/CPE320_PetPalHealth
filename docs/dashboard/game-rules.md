# กติกาเกม: dashboard (dashboard)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Design agent · ผู้ตรวจ: เพื่อน B · อ้างอิง: requirements.md, ux-flow.md

## 1. ค่าหลัก

| ชื่อค่า (ใช้ในโค้ด) | ความหมาย | ค่า | หน่วย | อ้างถึง |
|---|---|---|---|---|
| `food_score` | คะแนนอาหาร | 0 ถึง 100 | เปอร์เซ็นต์ (%) | AC-1, AC-4 |
| `steps_score` | คะแนนการก้าวเดิน | 0 ถึง 100 | เปอร์เซ็นต์ (%) | AC-1, AC-4 |
| `water_score` | คะแนนการดื่มน้ำ | 0 ถึง 100 | เปอร์เซ็นต์ (%) | AC-1, AC-4 |
| `total_score` | คะแนนสุขภาพรวมคำนวณจาก `(food_score + steps_score + water_score) / 3` (Cap สูงสุดไม่เกิน 100 และปัดเศษเป็น Integer) | 0 ถึง 100 | เปอร์เซ็นต์ (%) | AC-1 |
| `alert_queue_interval` | ระยะเวลาในการหมุนเวียนข้อความแจ้งเตือนใน Dynamic Queue | 5 | วินาที (s) | AC-3 |
| `reset_time` | เวลาตัดรอบวันใหม่และรีเซ็ตข้อมูลสุขภาพประจำวัน (อิง Server Time) | 05:00 | น. (ICT) | AC-5 |

## 3. เหตุการณ์และผลลัพธ์

| เหตุการณ์ | ค่าก่อน | ค่าหลัง | หมายเหตุ |

| คำนวณคะแนนรวมเมื่อ Food = 80, Steps = 90, Water = 70 | Food: 80, Steps: 90, Water: 70 | Total: 80 (`(80+90+70)/3 = 80`), Pet Mood: `SMILING` | AC-1, AC-2 |
| คำนวณคะแนนรวมเมื่อ Food = 50, Steps = 40, Water = 30 | Food: 50, Steps: 40, Water: 30 | Total: 40 (`(50+40+30)/3 = 40`), Pet Mood: `DAZED` | AC-1, AC-2 |
| คำนวณคะแนนรวมเมื่อคะแนนทุกหมวดเท่ากับ 100 | Food: 100, Steps: 100, Water: 100 | Total: 100 (`(100+100+100)/3 = 100`), Pet Mood: `CHEERFUL` | AC-1, AC-2 |
| คำนวณคะแนนรวมเมื่อคะแนนทุกหมวดเท่ากับ 0 | Food: 0, Steps: 0, Water: 0 | Total: 0 (`(0+0+0)/3 = 0`), Pet Mood: `CRYING` | AC-1, AC-2 |

## 4. พฤติกรรมที่ขอบเขต

| กรณี | ผลลัพธ์ที่ทดสอบได้ |
|---|---|
| คะแนนรวมจากการคำนวณเกิน 100% (เช่น Food = 120, Steps = 120, Water = 120 ได้ผลลัพธ์ 120%) | ระบบทำการ Cap ค่าสูงสุดไว้ที่ 100% และแสดงผลบน UI เป็น 100% พร้อมแสดงอารมณ์สัตว์เลี้ยงเป็น `CHEERFUL` |
| ผู้ใช้แก้ไขปัญหาใน Priority 1 สำเร็จขณะข้อความกำลังแสดงผลอยู่ | ระบบคัดชื่อข้อความ Priority 1 ออกจาก Dynamic Queue ทันที และข้ามไปแสดงข้อความในลำดับถัดไปทันทีโดยไม่ต้องรอครบรอบ 5 วินาที |
| เวลา Server Time เปลี่ยนผ่านเข้าสู่ช่วงเวลา 05:00 น. (ICT) พอดีขณะผู้ใช้เปิดหน้า Dashboard ค้างไว้ (Foreground Crossing) | หน้าจอ Dashboard ทำการรีเฟรชข้อมูลและรีเซ็ตค่าสถานะสุขภาพประจำวันเป็นค่าเริ่มต้นของวันใหม่โดยอัตโนมัติทันที |
| ข้อมูลคะแนนในหมวดหมู่ใดหมวดหมู่หนึ่งเป็นค่าติดลบหรือข้อมูลว่าง (Null) | ระบบกำหนดให้คะแนนหมวดนั้นมีค่าเท่ากับ 0 ก่อนนำไปคำนวณสูตรเฉลี่ยหาร 3 เพื่อป้องกันข้อผิดพลาด |
| คะแนนรวมคำนวณออกมาเป็นทศนิยม (เช่น Food = 70, Steps = 70, Water = 57 -> ผลรวม 65.66%) | ระบบทำการปัดเศษและแสดงผลบน UI เป็นจำนวนเต็ม (Integer) เสมอ (แสดงผลเป็น 66%) |

## 5. คำถามถึง Product

1. ข้อเสนอแนะจาก Design: ทีม Design เสนอให้ใช้ภาพ Asset สัตว์เลี้ยงแบบ Vector SVG หรือ PNG ที่รองรับ Responsive Layout ทุกขนาดหน้าจอ
   - กติกาชั่วคราวเพื่อให้ Dev พัฒนาต่อได้ทันที (Fallback Rule): ให้ Developer กำหนดขนาดกรอบรูปภาพสัตว์เลี้ยงเป็นแบบ Fixed Aspect Ratio (ความกว้าง 100% ของ Container, ความสูงปรับตามสัดส่วน 1:1 ขนาดสูงสุด 240x240 พิกเซล)
   - การประเมินสถานะการบล็อก: Blocking: ไม่ใช่

2. ข้อเสนอแนะจาก Design: ยืนยันการใช้ Timezone มาตรฐานร่วมกันที่ 05:00 น. (ICT) สำหรับผู้ใช้ทุกคน เพื่อความสอดคล้องของระบบตัดรอบวัน
   - กติกาชั่วคราวเพื่อให้ Dev พัฒนาต่อได้ทันที (Fallback Rule): ให้ระบบอ้างอิงเวลาตามระบบ UTC+7 (ICT) จาก Server เป็นหลักในการคำนวณการตัดรอบ 05:00 น. เสมอ
   - การประเมินสถานะการบล็อก: Blocking: ไม่ใช่
