# Brief: Unified Pet Dashboard & Global Status Feature (dashboard)

## Overview
หน้าจอ Dashboard ภาพรวมพลังงานชีวิตของสัตว์เลี้ยงในแอปพลิเคชัน PetPal Health ทำหน้าที่รวบรวมข้อมูลจาก 3 ฟีเจอร์หลัก (อาหาร `food`, การเดิน `steps`, และการดื่มน้ำ `water`) มาคำนวณคะแนนเฉลี่ยพลังงานชีวิต แสดงอารมณ์ของสัตว์เลี้ยงแบบเรียลไทม์ ระบบแจ้งเตือนข้อความวนลูปอัจฉริยะ (Rotating Bubble) และรักษากฎการตัดรอบวันเวลา 05:00 น. ร่วมกันอย่างเป็นระบบ

## 1. Average Energy Score Calculation & Integer Display
- **Cap Rule (การจำกัดเพดานคะแนน):** ผลงานของแต่ละฟีเจอร์จะถูกคิดเปอร์เซ็นต์และ **ถูก Cap ค่าสูงสุดไว้ที่ไม่เกิน 100% เสมอ**
- **สูตรคำนวณคะแนนรวมชีวิต (Average Score):**
  $$\text{Score}_{\text{total}} = \frac{\%_{\text{food}} + \%_{\text{steps}} + \%_{\text{water}}}{3}$$
- **Integer Display Rule (แสดงผลเป็นจำนวนเต็ม):** ตัวเลขเปอร์เซ็นต์ที่แสดงผลบนหน้าจอ Dashboard (คะแนนรวม และ % รายฟีเจอร์) **จะต้องแสดงเป็นจำนวนเต็ม (Integer 0-100%) เสมอ** โดยใช้ระบบปัดเศษทศนิยม (`Math.round`) ก่อนนำมาเรนเดอร์ UI เพื่อให้ Designer (C) และ Developer (B) ทำงานได้ชัดเจน

## 2. Global Pet Expression Mapping (เกณฑ์อารมณ์สัตว์เลี้ยง)
รูปร่างกายภาพของสัตว์เลี้ยงบนหน้า Dashboard จะแสดงผลปกติ (เน้นความน่ารัก) แต่สีหน้าและอารมณ์ (Expression) จะเปลี่ยนไปตามช่วงคะแนนรวมพลังงานชีวิต (จำนวนเต็ม) ดังนี้:
- **คะแนน 0% – 30%:** ร้องไห้ 😢
- **คะแนน 31% – 60%:** เหม่อลอยตาโบ๋ว 👁️👄👁️
- **คะแนน 61% – 80%:** ยิ้มแบบออรุ่มเจ๊าะ 😏
- **คะแนน 81% – 100%:** ยิ้มร่าเริงดีใจ 😁🎉

## 3. Rotating Bubble & Priority Queue (ระบบแจ้งเตือนวนลูปทุก 5 วินาที พร้อมบังคับใช้ Text Strings เป๊ะๆ)
หากมีฟีเจอร์ใดทำคะแนนไม่ถึงเกณฑ์ (< 80%) หรือเข้าเงื่อนไขพิเศษ ระบบจะแสดงข้อความเตือนเหนือหัวสัตว์เลี้ยงแบบ **สลับวนลูปทุกๆ 5 วินาที** พร้อมกฎ **Dynamic Queue Rule (คัดชื่อออกจากคิวทันทีเมื่อแก้ปัญหาสำเร็จในรอบ 5 วินาทีถัดไป)** โดย **ห้ามดัดแปลงข้อความเด็ดขาด** ให้ใช้ข้อความตามนี้เท่านั้น:
- **Priority 1 (สูงสุด - Overeating Flag):** อาหารเกินเป้าหมายจนหลอดเป็นสีแดง (**กินเกิน > 100 kcal**)
  - *ข้อความเตือน (บังคับใช้ข้อความนี้เป๊ะๆ):* `"แต่วันนี้ฉันอิ่มและอืดเกินไปน้าาาา วันต่อไปต้องลดการกินแล้ว"` 
  - *(หมายเหตุ: หลอดอาหารแสดงเป็นสีแดง แม้คะแนนรวมจะถูกคิดที่ 100% และข้อความนี้จะถูกบังคับดึงขึ้นมาแสดงทันที)*
- **Priority 2:** น้ำดื่มไม่ถึง 80% 
  - *ข้อความเตือน (บังคับใช้ข้อความนี้เป๊ะๆ):* `"ดื่มน้ำๆ"`
- **Priority 3:** ก้าวเดินไม่ถึง 80% 
  - *ข้อความเตือน (บังคับใช้ข้อความนี้เป๊ะๆ):* `"ขยับร่างกายหน่อย อีกนิดๆ"`
- **Priority 4 (ต่ำสุด):** อาหารไม่ถึง 80% 
  - *ข้อความเตือน (บังคับใช้ข้อความนี้เป๊ะๆ):* `"ฉันหิว"`

## 4. UI Component Details & Layout (รายละเอียดการจัดวาง)
หน้าจอ Dashboard จัดวาง Widget ย่อย 3 โซนให้ชัดเจน:
- **โซนน้ำ (Water Widget):** แสดงหลอดพลังงานน้ำ (ตัน 100%) เป็นจำนวนเต็ม + ตัวเลขจำนวนแก้วที่ดื่มวันนี้เทียบกับเป้าหมาย
- **โซนก้าวเดิน (Steps Widget):** แสดงจำนวนก้าวเดินปัจจุบันเทียบกับเป้าหมายประจำวัน เป็นตัวเลขจำนวนเต็ม
- **โซนอาหาร (Food Widget):** แสดงแคลอรี่ที่ทานเทียบกับเป้าหมาย + ป้ายกำกับแจ้งเตือนพิเศษ (เช่น โซเดียมสูง / น้ำตาลสูง) พร้อมเงื่อนไขเปลี่ยนหลอดเป็นสีแดงเมื่อเกิด Overeating

## 5. Reset Rule (กฎการตัดรอบวัน)
- รีเซ็ตสถิติทั้งหมดพร้อมกันใน **เวลา 05:00 น. (ICT / UTC+7)** ของทุกวัน (อ้างอิง Server Time เสมอ)
- ช่วงเวลา 04:59 น. ยังคงแสดงข้อมูลและสถิติของวันก่อนหน้าปกติ

## 6. Edge Cases Requirement (ครบถ้วน 5 ข้อสมบูรณ์)
ครอบคลุม Edge Cases สำคัญ 5 ข้อ:
1. **การ Cap ค่าสูงสุด:** เมื่อคะแนนดิบของฟีเจอร์ใดเกิน 100% ระบบต้อง Cap ไว้ที่ 100% ก่อนคำนวณคะแนนรวม
2. **การปัดเศษทศนิยม:** ตัวเลขเปอร์เซ็นต์ทั้งหมดต้องปัดเศษเป็นจำนวนเต็ม (`Math.round`) ก่อนเรนเดอร์ UI
3. **กรณีสุขภาพสมบูรณ์ 100% ทุกด้าน:** หากไม่มีข้อความแจ้งเตือนในคิวเลย Bubble ข้อความจะซ่อนอัตโนมัติ และสัตว์เลี้ยงแสดงรอยยิ้มร่าเริง
4. **การตัดรอบข้ามวัน (05:00 น.):** กรณีเปิดแอปค้างไว้ข้ามเวลา 05:00 น. (ICT) ระบบจะ Trigger รีเซ็ตข้อมูลเป็น 0% และอัปเดตหน้าจออัตโนมัติทันที
5. **การซิงค์ข้อมูลช้า / Offline Cache:** กรณีสัญญาณอินเทอร์เน็ตไม่เสถียรหรือโหลดข้อมูลจากเซิร์ฟเวอร์ช้า UI จะดึงข้อมูลคะแนนล่าสุดจาก Local Cache มาแสดงผลชั่วคราวเพื่อป้องกันหน้าจอค้าง และซิงค์ข้อมูลจริงทันทีเมื่อเครือข่ายพร้อม
