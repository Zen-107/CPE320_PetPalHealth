## 3. เหตุการณ์และผลลัพธ์

| เหตุการณ์ | ค่าก่อน | ค่าหลัง | หมายเหตุ |
|---|---|---|---|
| ผู้ใช้เดินได้ 5,000 จากเป้าหมาย 10,000 ก้าว (50%) | current_steps: 5,000, goal: 10,000 (% Goal: 50%) | รูปร่างสัตว์เลี้ยง: จ่ำม่ำ | อ้าง AC-5 |
| ผู้ใช้เดินได้ 10,000 จากเป้าหมาย 10,000 ก้าว (100%) | current_steps: 10,000, goal: 10,000 (% Goal: 100%) | รูปร่างสัตว์เลี้ยง: มีกล้ามขา, เปอร์เซ็นต์สะสมหยุดอยู่ที่ 100% | อ้าง AC-6 |
| ถึงเวลา 05:00:00 น. ตัดรอบวันใหม่ | current_steps: 8,000, step_goal_change_count: 1 | current_steps: 0, goal_progress_bar: 0%, step_goal_change_count: 0 | อ้าง AC-7 |
| ผู้ใช้เปลี่ยนเป้าหมายครั้งที่ 1 ของวัน | step_goal_change_count: 0, daily_step_goal: 10,000 | step_goal_change_count: 1, daily_step_goal: ค่าที่เลือกใหม่ | อ้าง AC-2, AC-3 |

## 4. พฤติกรรมที่ขอบเขต

| กรณี | ผลลัพธ์ที่ทดสอบได้ |
|---|---|
| ค่าก้าวเดินเกินเป้าหมาย 100% (เช่น เดินได้ 12,000 จาก 10,000 ก้าว) | หลอดพลังงาน (% Goal) จะหยุดแสดงผลสูงสุดที่ 100% และรูปร่างสัตว์เลี้ยงจะถูกล็อกไว้ที่สถานะ "มีกล้ามขา" โดยไม่เกินขอบเขต |
| ผู้ใช้พยายามเปลี่ยนเป้าหมายเป็นครั้งที่ 2 ในวันเดียวกัน (ก่อน 05:00 น.) | ปุ่มเปลี่ยนเป้าหมายจะถูก Disabled (เป็นสีเทา) และแสดงข้อความแจ้งเตือน "คุณสามารถปรับเปลี่ยนเป้าหมายได้เพียง 1 ครั้งต่อวันเท่านั้น" |
| ผู้ใช้ปรับเปลี่ยนเป้าหมายหลังเวลาตัดรอบ 05:00 น. (เช่น เวลา 06:00 น.) | เป้าหมายใหม่จะถูกบันทึกไว้ แต่จะมีผลบังคับใช้จริงตั้งแต่วันถัดไป (นับรอบ 05:00 น. ของวันพรุ่งนี้) |
| การปฏิเสธสิทธิ์การเข้าถึงเซนเซอร์ (Permission Denied) | ระบบล็อกฟังก์ชันนับก้าวทั้งหมด แสดง Pop-up แจ้งเตือน และแสดงปุ่ม Shortcut พาผู้ใช้ไปยังหน้า Settings ของระบบปฏิบัติการ |
| เครื่องดับระหว่างวันเนื่องจากแบตเตอรี่หมด และเปิดเครื่องขึ้นมาใหม่ | ระบบดึงข้อมูลก้าวล่าสุดที่บันทึกไว้ใน Local Storage มาแสดงผลทันทีโดยไม่มีข้อมูลสูญหาย |
| การเปลี่ยน Timezone หรือเวลาในเครื่องเพื่อหลอกระบบรีเซ็ตสถิติ | ระบบยึดเวลาตาม Network/Server Time เท่านั้น ป้องกันการรีเซ็ตสถิติย้อนหลัง และจำนวนก้าวไม่ถูกแก้ไข |
| การเปิดแอปค้างไว้ข้ามช่วงเวลา 05:00 น. (Foreground Crossing) | ระบบทำการรีเฟรชหน้าจออัตโนมัติ ตัดรอบสถิติ รีเซ็ตหลอดพลังงานและจำนวนก้าวเป็น 0 และเริ่มนับรอบวันใหม่ทันทีโดยไม่ต้องปิดเปิดแอปใหม่ |

## 5. คำถามถึง Product

- รูปแบบการแจ้งเตือน (Push Notification) เมื่อผู้ใช้ใกล้ทำเป้าหมายสำเร็จ 100% ควรส่งล่วงหน้าที่ก้าวเท่าไหร่ (เช่น เหลืออีก 500 ก้าว)? (ยังไม่มีกำหนดใน requirements)
- ในกรณีที่อุปกรณ์ของผู้ใช้ไม่มีฮาร์ดแวร์เซนเซอร์นับก้าว (Hardware Step Counter) ระบบจะมี Fallback อย่างไร หรือบังคับรองรับเฉพาะเครื่องที่มีเซนเซอร์เท่านั้น? (ยังไม่มีกำหนดใน requirements)
