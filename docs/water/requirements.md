# Requirements: การบันทึกการกินน้ำ (water)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Product agent · ผู้ตรวจ: เพื่อน A · อ้างอิง Issue: #101

## 1. สรุปฟีเจอร์
ฟีเจอร์นี้ช่วยให้เจ้าของสัตว์เลี้ยงบันทึกปริมาณการดื่มน้ำในแต่ละวันเพื่อสุขภาพที่ดี และเชื่อมโยงกับการแสดงผล "หลอดพลังงานน้ำ" ของสัตว์เลี้ยงในแอป PetPal Health โดยพลังงานจะลดลงตามเวลาจริงและส่งผลต่อท่าทางของสัตว์เลี้ยง

## 2. User stories

| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | เจ้าของสัตว์เลี้ยง | กดปุ่มบันทึกการดื่มน้ำ 1 แก้ว | เพิ่มระดับพลังงานน้ำให้สัตว์เลี้ยงและอัปเดตเป้าหมายประจำวัน |
| US-2 | เจ้าของสัตว์เลี้ยง | เห็นหลอดพลังงานน้ำและสถานะของสัตว์เลี้ยงเปลี่ยนแปลงตามเวลาและปริมาณน้ำ | รู้สึกผูกพันและทราบระดับความสดชื่นของสัตว์เลี้ยงในปัจจุบัน |

## 3. Acceptance criteria

| ID | อ้างถึง | เงื่อนไข (ก่อน /เมื่อ / แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | ก่อน: หลอดพลังงานน้ำอยู่ที่ 0%<br>เมื่อ: ผู้ใช้กดปุ่มบันทึกน้ำ 1 แก้ว<br>แล้ว: หลอดพลังงานน้ำเพิ่มขึ้นทันที และ UI แสดงผลที่ 12.5% | ค่าความก้าวหน้า (Progress Bar) เท่ากับ 12.5% และจำนวนแก้วที่ดื่มสะสมแสดงผลเป็น 1 / 8 แก้ว |
| AC-2 | US-1 | ก่อน: ผู้ใช้กดบันทึกน้ำครั้งแรกสำเร็จ<br>เมื่อ: ผู้ใช้กดปุ่มบันทึกซ้ำภายใน 3 นาที (ยังไม่พ้น 5 นาที)<br>แล้ว: ระบบแสดงข้อความแจ้งเตือนการสแปมปุ่ม | ปรากฏ Toast/Alert ข้อความ "กรุณารอสักครู่ (สามารถกดได้อีกครั้งใน X นาที Y วินาที)" และค่าพลังงานไม่เพิ่มขึ้น |
| AC-3 | US-1 | ก่อน: ผู้ใช้กดบันทึกน้ำครบ 8 ครั้งใน 1 วัน<br>เมื่อ: ผู้ใช้กดบันทึกน้ำครั้งที่ 9<br>แล้ว: หลอดพลังงานน้ำหยุดที่ 100% ไม่เกินกว่านี้ แต่บันทึกจำนวนแก้วสะสมเป็น 9/8 แก้วได้ | หลอดพลังงานน้ำคงที่ที่ 100.0% |
| AC-4 | US-2 | ก่อน: หลอดพลังงานน้ำอยู่ที่ 60%<br>เมื่อ: เวลาผ่านไป 1 ชั่วโมงโดยไม่มีการบันทึกน้ำเพิ่ม<br>แล้ว: หลอดพลังงานน้ำลดลงอัตโนมัติ | หลอดพลังงานน้ำลดลงเหลือ 57.5% (ลดลง 2.5% ต่อ 1 ชั่วโมง สมมติฐานอัตราลด) และอัปเดตสถานะสัตว์เลี้ยงตามช่วงเรจที่กำหนด |
| AC-5 | US-2 | ก่อน: หลอดพลังงานน้ำอยู่ที่ 60%<br>เมื่อ: หลอดพลังงานน้ำลดลงเหลือ 59%<br>แล้ว: รูปภาพ/อนิเมชันสัตว์เลี้ยงเปลี่ยนจากโหมดสดชื่นเป็นโหมดเริ่มเพลีย | ตรวจสอบว่า UI สัตว์เลี้ยงเปลี่ยนสถานะตรงตามเรจ 30% - 59% |

## 4. Edge cases

| ID | สถานการณ์ | ผลที่คาดหวังที่ทดสอบได้ |
|---|---|---|
| EC-1 | ผู้ใช้เปลี่ยนเวลาของระบบเครื่องโทรศัพท์ย้อนหลังเพื่อโกงเวลาลดลงของหลอดพลังงานน้ำ | ระบบต้องตรวจสอบเวลาจาก Timestamp ล่าสุดใน Local Storage หากพบว่าเวลาปัจจุบันน้อยกว่าเวลาบันทึก, ให้ใช้เวลาล่าสุดที่มีการบันทึกจริงเพื่อคำนวณการลดลงของพลังงาน ป้องกันการโกงเวลา |
| EC-2 | แอปพลิเคชันถูกปิด (Force Close) หรือรีสตาร์ทเครื่อง ระหว่างที่หลอดพลังงานน้ำควรจะลดลง | เมื่อเปิดแอปขึ้นมาใหม่ ระบบต้องคำนวณส่วนต่างของเวลา (Elapsed Time) นับจาก Timestamp ล่าสุดที่บันทึกไว้ใน Local Storage จนถึงเวลาปัจจุบัน แล้วหักลบหลอดพลังงานตามจำนวนชั่วโมงที่หายไปทันทีในหน้าจอหลัก |
| EC-3 | พื้นที่จัดเก็บในเครื่อง (Local Storage) เต็ม ไม่สามารถบันทึกข้อมูลลง SharedPreferences / Hive ได้ | ระบบแสดงข้อความแจ้งเตือน "พื้นที่จัดเก็บในเครื่องไม่เพียงพอ กรุณาเคลียร์พื้นที่" และคงค่าสถานะเดิมไว้โดยไม่ทำให้แอปพลิเคชันค้าง (Crash) |

## 5. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ไม่มีการเชื่อมต่อ Backend หรือ Server ภายนอกเพื่อซิงค์ข้อมูลข้ามอุปกรณ์
- ไม่มีระบบ Social, การดูเพื่อน หรือการแชร์สถานะสัตว์เลี้ยงร่วมกัน
- ไม่มีระบบร้านค้าสำหรับซื้อของแต่งตัวหรือไอเทมเสริมให้สัตว์เลี้ยง

## 6. ข้อมูลที่ใช้ (ข้อมูลสมมติเท่านั้น)

| ข้อมูล | ชนิด/หน่วย | เก็บที่ไหน |
|---|---|---|
| current_water_energy | Float (0.0 - 100.0 เปอร์เซ็นต์) | Local Storage (SharedPreferences / Hive) |
| daily_water_count | Integer (จำนวนแก้ว) | Local Storage (SharedPreferences / Hive) |
| last_logged_timestamp | Integer (Unix Epoch Timestamp เป็นมิลลิวินาที) | Local Storage (SharedPreferences / Hive) |
| last_energy_decay_timestamp | Integer (Unix Epoch Timestamp เป็นมิลลิวินาที) | Local Storage (SharedPreferences / Hive) |

## 7. คำถามที่ยังเปิดอยู่
- อัตราการลดลงของหลอดพลังงานน้ำที่แน่ชัดต่อ 1 ชั่วโมงควรเป็นกี่เปอร์เซ็นต์ เพื่อให้สอดคล้องกับพฤติกรรมจริงของผู้ใช้ (ในสเปกเบื้องต้นสมมติให้ลดแบบสัดส่วนเท่ากันทุกชั่วโมงจนถึง 0%)
- หากข้ามวันใหม่ (เที่ยงคืน 00:00) ปริมาณน้ำสะสมและหลอดพลังงานจะถูกรีเซ็ตเป็น 0% อัตโนมัติทันทีเลยหรือไม่ หรือมีระบบเตือนสรุปผลของวันก่อนหน้าหรือไม่
