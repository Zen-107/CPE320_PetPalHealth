# Requirements: ฟีเจอร์การบันทึกการกินน้ำ (water)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Product agent · ผู้ตรวจ: เพื่อน A · อ้างอิง Issue: #101

## 1. สรุปฟีเจอร์
ฟีเจอร์นี้ช่วยให้เจ้าของสัตว์เลี้ยงบันทึกปริมาณการดื่มน้ำประจำวันได้สะดวก พร้อมเชื่อมโยงกับหลอดพลังงานและสถานะอารมณ์ของสัตว์เลี้ยงในแอป PetPal Health เพื่อกระตุ้นพฤติกรรมการดูแลสุขภาพ ทั้งยังมีระบบป้องกันการสแปมและสรุปรายงานรายเดือนเพื่อติดตามย้อนหลัง

## 2. User stories

| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | เจ้าของสัตว์เลี้ยง | กดบันทึกปริมาณน้ำที่ดื่มทีละ 1 แก้ว | เพิ่มหลอดพลังงานและดูปฏิกิริยาของสัตว์เลี้ยงตามจริง |
| US-2 | เจ้าของสัตว์เลี้ยง | ดูรายงานสรุปประวัติการดื่มน้ำรายเดือนและค่าเฉลี่ยต่อวัน | ติดตามพฤติกรรมการดื่มน้ำย้อนหลังในแต่ละเดือนได้ |
| US-3 | เจ้าของสัตว์เลี้ยง | ระบบรีเซ็ตค่าการดื่มน้ำและหลอดพลังงานเป็น 0 โดยอัตโนมัติ | เริ่มต้นวันใหม่ด้วยเป้าหมายการดื่มน้ำใหม่ได้ทันที |

## 3. Acceptance criteria

| ID | อ้างถึง | เงื่อนไข (ก่อน / เมื่อ / แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | ก่อน: หลอดพลังงานอยู่ที่ 0% (0 แก้ว) <br> เมื่อ: ผู้ใช้กดปุ่มบันทึกน้ำ 1 แก้ว <br> แล้ว: หลอดพลังงานเพิ่มขึ้น 12.5% และจำนวนแก้วแสดงผลเป็น 1 แก้ว | พลังงาน = 12.5%, จำนวนแก้ว = 1 แก้ว |
| AC-2 | US-1 | ก่อน: บันทึกน้ำสะสม 0 - 3 แก้ว <br> เมื่อ: ตรวจสอบสถานะสัตว์เลี้ยง <br> แล้ว: สัตว์เลี้ยงแสดงสถานะ "เหี่ยวเฉา ป่วย ใกล้ตาย" | ช่วงพลังงาน 0% - 37.5% |
| AC-3 | US-1 | ก่อน: บันทึกน้ำสะสม 4 - 6 แก้ว <br> เมื่อ: ตรวจสอบสถานะสัตว์เลี้ยง <br> แล้ว: สัตว์เลี้ยงแสดงสถานะ "เริ่มเพลีย อ่อนแรง แลบลิ้น" | ช่วงพลังงาน 50% - 75% |
| AC-4 | US-1 | ก่อน: บันทึกน้ำสะสม 7 แก้วขึ้นไป <br> เมื่อ: ตรวจสอบสถานะสัตว์เลี้ยง <br> แล้ว: สัตว์เลี้ยงแสดงสถานะ "สดชื่น ร่าเริง มีความสุข" และหลอดพลังงานแสดงผลสูงสุดที่ 100% (แม้จะดื่มเกิน 8 แก้ว) | ช่วงพลังงาน 87.5% - 100%+ |
| AC-5 | US-1 | ก่อน: ผู้ใช้กดบันทึกน้ำไปแล้ว 2 ครั้งในเวลาปัจจุบัน <br> เมื่อ: ผู้ใช้พยายามกดบันทึกครั้งที่ 3 ภายในระยะเวลา 5 นาที <br> แล้ว: ระบบบล็อกการบันทึกและแสดง Toast/Alert แจ้งเตือนการกดถี่เกินไป | บันทึกเพิ่มไม่ได้, แสดงข้อความแจ้งเตือนภายใน 0.5 วินาที |
| AC-6 | US-3 | ก่อน: เวลาในระบบถึง 05:00 น. ของวันใหม่ <br> เมื่อ: ระบบทำการรีเซ็ตประจำวัน <br> แล้ว: จำนวนแก้วน้ำและหลอดพลังงานถูกรีเซ็ตกลับเป็น 0 และ 0% | จำนวนแก้ว = 0, พลังงาน = 0% |
| AC-7 | US-2 | ก่อน: หน้าจอรายงานสรุปรายเดือน <br> เมื่อ: ผู้ใช้เลือกดูข้อมูลเดือนปัจจุบัน <br> แล้ว: แสดงตารางประวัติรายวัน (จำนวนแก้ว/วัน) และค่าเฉลี่ยการดื่มน้ำต่อวันของเดือนนั้น | แสดงรายการครบทุกวันในเดือน และค่าเฉลี่ยคำนวณถูกต้อง (ทศนิยม 1 ตำแหน่ง) |

## 4. Edge cases

| ID | สถานการณ์ | ผลที่คาดหวัง |
|---|---|---|
| EC-1 | ผู้ใช้พยายามกดบันทึกแก้วที่ 3 ภายในเวลา 4นาที 59วินาที นับจากการกดครั้งแรก | ระบบบล็อกการบันทึก แสดง Toast เตือน และไม่เพิ่มจำนวนแก้วน้ำ |
| EC-2 | ผู้ใช้ดื่มน้ำต่อเนื่องเกินเป้าหมาย (เช่น 15 แก้ว หรือ 187.5%) | หลอดพลังงานหยุดแสดงผลสูงสุดที่ 100% แต่ระบบยังคงบันทึกจำนวนแก้วสะสมจริง (15 แก้ว) เพื่อนำไปคำนวณค่าเฉลี่ยรายเดือน |
| EC-3 | แอปพลิเคชันถูกปิดและเปิดใหม่ในช่วงเวลาระหว่างวัน (ก่อน 05:00 น.) | ข้อมูลจำนวนแก้ว พลังงาน และเวลาล็อกล่าสุดสำหรับการจับเวลา Anti-Spam ยังคงอยู่ครบถ้วนจาก Local Storage |
| EC-4 | ถึงเวลา 05:00 น. พอดีขณะที่ผู้ใช้กำลังเปิดหน้าจอแอปพลิเคชันอยู่ | หน้าจออัปเดตสถานะเป็น 0 แก้วและ 0% โดยอัตโนมัติ พร้อมบันทึกประวัติของวันก่อนหน้าลงฐานข้อมูล Local Storage |

## 5. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ไม่มีระบบลดพลังงานน้ำตามเวลาระหว่างวัน (Decay)
- ยังไม่ต่อ Backend หรือ Server ภายนอกเพื่อซิงค์ข้อมูล (เก็บเฉพาะในเครื่องเท่านั้น)
- ยังไม่มีระบบ Social / ดูเพื่อนร่วมกัน
- ยังไม่มีระบบซื้อของแต่งตัวสัตว์เลี้ยงเพิ่มเติม
- ไม่มีฟังก์ชันพิมพ์รายงานออกเครื่องพิมพ์ภายนอกโดยตรง (รองรับแค่การแสดงผลหน้าจอสรุปรายเดือนในแอปเท่านั้น)

## 6. ข้อมูลที่ใช้ (ข้อมูลสมมติเท่านั้น)

| ข้อมูล | ชนิด/หน่วย | เก็บที่ไหน |
|---|---|---|
| current_water_count | Integer (จำนวนแก้ว) | Local Storage (SharedPreferences / Hive) |
| water_energy_bar | Float (เปอร์เซ็นต์ 0.0 - 100.0+) | Local Storage (SharedPreferences / Hive) |
| last_click_timestamp | Timestamp (เวลาที่กดล่าสุด) | Local Storage (SharedPreferences / Hive) |
| daily_history_log | JSON Array (วันที่, จำนวนแก้ว) | Local Storage (SharedPreferences / Hive) |
| click_count_in_window | Integer (จำนวนครั้งในรอบ 5 นาที) | หน่วยความจำชั่วคราวในแอป (Runtime Memory) |

## 7. คำถามที่ยังเปิดอยู่
- รูปแบบการแสดงผล Toast เตือนกรณี Anti-Spam ควรหายไปเองอัตโนมัติภายในกี่วินาที (เบื้องต้นกำหนดไว้ที่ 3 วินาที)?
- ในหน้าสรุปรายงานรายเดือน หากเดือนนั้นไม่มีข้อมูลการบันทึกในบางวัน ระบบควรบันทึกค่าเป็น 0 แก้วเพื่อนำไปคำนวณค่าเฉลี่ยด้วยหรือไม่?
