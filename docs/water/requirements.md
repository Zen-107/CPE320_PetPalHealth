# Requirements: ฟีเจอร์การบันทึกการกินน้ำ (water)

> สถานะ: พร้อมรีวิว · ผู้เขียน: Product agent · ผู้ตรวจ: เพื่อน A · อ้างอิง Issue: #101

## 1. สรุปฟีเจอร์
ฟีเจอร์บันทึกการกินน้ำช่วยให้ผู้ใช้ติดตามปริมาณน้ำดื่มประจำวันได้สะดวกผ่านปุ่มบันทึก พร้อมเชื่อมโยงกับหลอดพลังงานและอารมณ์ของสัตว์เลี้ยงในแอป PetPal Health เพื่อสร้างแรงจูงใจในการดูแลสุขภาพของตนเองและสัตว์เลี้ยง

## 2. User stories

| ID | ในฐานะ | ฉันอยาก | เพื่อ |
|---|---|---|---|
| US-1 | เจ้าของสัตว์เลี้ยง | กดบันทึกปริมาณการดื่มน้ำของตนเองทีละ 1 แก้ว | เพิ่มระดับพลังงานน้ำและดูแลสุขภาพของตนเอง |
| US-2 | เจ้าของสัตว์เลี้ยง | เห็นสถานะอารมณ์และหลอดพลังงานของสัตว์เลี้ยงเปลี่ยนไปตามปริมาณน้ำที่ดื่มสะสม | ทราบว่าสัตว์เลี้ยงมีสุขภาพและความสุขสอดคล้องกับการดื่มน้ำของตน |
| US-3 | เจ้าของสัตว์เลี้ยง | ระบบรีเซ็ตข้อมูลน้ำและหลอดพลังงานเป็น 0 โดยอัตโนมัติในเวลา 05:00 น. ของทุกวัน | เริ่มต้นวันใหม่ด้วยเป้าหมายการดื่มน้ำที่ถูกต้อง |

## 3. Acceptance criteria

| ID | อ้างถึง | เงื่อนไข (ก่อน / เมื่อ / แล้ว) | ค่าที่ทดสอบได้ |
|---|---|---|---|
| AC-1 | US-1 | ก่อน: หลอดพลังงานอยู่ที่ 0%<br>เมื่อ: ผู้ใช้กดปุ่มบันทึกการดื่มน้ำ 1 แก้ว<br>แล้ว: จำนวนแก้วสะสมเพิ่มเป็น 1 แก้ว และหลอดพลังงานเพิ่มขึ้น 12.5% | จำนวนแก้ว = 1, หลอดพลังงาน = 12.5% |
| AC-2 | US-1 | ก่อน: ผู้ใช้กดบันทึกน้ำครั้งล่าสุดเมื่อ 0 นาทีที่แล้ว (กดไปแล้ว 2 ครั้งติดกันภายใน 5 นาที)<br>เมื่อ: ผู้ใช้พยายามกดปุ่มบันทึกน้ำอีกครั้งในทันที<br>แล้ว: ระบบแสดงข้อความแจ้งเตือนและไม่อนุญาตให้บันทึก | แสดง Toast/Alert ข้อความแจ้งเตือน และจำนวนแก้วไม่เพิ่มขึ้น |
| AC-3 | US-2 | ก่อน: ผู้ใช้ดื่มน้ำสะสม 2 แก้ว (หลอดพลังงาน 25%)<br>เมื่อ: ผู้ใช้หน้าจอหลักของแอปพลิเคชัน<br>แล้ว: แสดงภาพสัตว์เลี้ยงในสถานะเหี่ยวเฉา ป่วย ใกล้ตาย | สถานะสัตว์เลี้ยงแสดงผล "เหี่ยวเฉา ป่วย ใกล้ตาย" และหลอดพลังงานแสดง 25% |
| AC-4 | US-2 | ก่อน: ผู้ใช้ดื่มน้ำสะสม 4 แก้ว (หลอดพลังงาน 50%)<br>เมื่อ: ผู้ใช้เปิดหน้าจอหลักของแอปพลิเคชัน<br>แล้ว: แสดงภาพสัตว์เลี้ยงในสถานะเริ่มเพลีย อ่อนแรง แลบลิ้น | สถานะสัตว์เลี้ยงแสดงผล "เริ่มเพลีย อ่อนแรง แลบลิ้น" และหลอดพลังงานแสดง 50% |
| AC-5 | US-2 | ก่อน: ผู้ใช้ดื่มน้ำสะสม 8 แก้ว (หลอดพลังงาน 100%)<br>เมื่อ: ผู้ใช้เปิดหน้าจอหลักของแอปพลิเคชัน<br>แล้ว: แสดงภาพสัตว์เลี้ยงในสถานะสดชื่น ร่าเริง มีความสุข (หยุดสะสมสูงสุดที่ 100%) | สถานะสัตว์เลี้ยงแสดงผล "สดชื่น ร่าเริง มีความสุข" และหลอดพลังงานแสดง 100% แม้จะกดดื่มเกิน 8 แก้ว |
| AC-6 | US-3 | ก่อน: เวลาในระบบคือ 04:59 น. และมีข้อมูลดื่มน้ำสะสม 5 แก้ว (หลอดพลังงาน 62.5%)<br>เมื่อ: เวลาในระบบเปลี่ยนเป็น 05:00 น.<br>แล้ว: จำนวนแก้วสะสมถูกรีเซ็ตเป็น 0 แก้ว และหลอดพลังงานถูกรีเซ็ตเป็น 0% | จำนวนแก้ว = 0, หลอดพลังงาน = 0% เมื่อเวลาถึง 05:00 น. |

## 4. Edge cases

| ID | สถานการณ์ | ผลที่คาดหวังที่ทดสอบได้ |
|---|---|---|
| EC-1 | ผู้ใช้กดบันทึกน้ำครบ 8 แก้วแล้ว (หลอดพลังงาน 100%) แล้วกดบันทึกเพิ่มอีก 1 แก้ว | จำนวนแก้วสะสมบันทึกเพิ่มเป็น 9 แก้ว แต่หลอดพลังงานและสถานะสัตว์เลี้ยงคงที่อยู่ที่ 100% และแสดงสัตว์เลี้ยงในสถานะสดชื่น ร่าเริง |
| EC-2 | แอปพลิเคชันถูกปิดและเปิดใหม(App Restart) ระหว่างวัน | ข้อมูลจำนวนแก้วสะสม เวลาที่กดบันทึกครั้งล่าสุด และหลอดพลังงานยังคงแสดงผลถูกต้องตามค่าที่บันทึกไว้ล่าสุดใน Local Storage |
| EC-3 | นาฬิกาของอุปกรณ์ของผู้ใช้ถูกปรับเปลี่ยนเวลาข้ามไปข้างหน้าหรือข้างหลัง | ระบบตรวจสอบเวลาจริง (System Time / Network Time) และดำเนินการรีเซ็ตข้อมูลเป็น 0 เมื่อถึงเวลา 05:00 น. ตามเงื่อนไขเวลาจริง |

## 5. สิ่งที่ไม่ทำในรอบนี้ (Out of scope)
- ไม่มีระบบลดพลังงานน้ำตามเวลาระหว่างวัน (Decay)
- ยังไม่เชื่อมต่อ Backend หรือ Server ภายนอก
- ยังไม่มีระบบ Social หรือการดูเพื่อนร่วมกัน
- ยังไม่มีระบบซื้อของหรือแต่งตัวสัตว์เลี้ยงเพิ่มเติม

## 6. ข้อมูลที่ใช้ (ข้อมูลสมมติเท่านั้น)

| ข้อมูล | ชนิด/หน่วย | เก็บที่ไหน |
|---|---|---|
| `water_count` | Integer (จำนวนแก้ว, เริ่มต้น 0) | Local Storage (SharedPreferences / Hive) |
| `water_energy` | Float (เปอร์เซ็นต์, 0.0 ถึง 100.0) | Local Storage (SharedPreferences / Hive) |
| `last_logged_timestamp` | DateTime (เวลาที่กดบันทึกครั้งล่าสุด) | Local Storage (SharedPreferences / Hive) |
| `last_reset_date` | String (รูปแบบ YYYY-MM-DD สำหรับเช็คการรีเซ็ต 05:00 น.) | Local Storage (SharedPreferences / Hive) |

## 7. คำถามที่ยังเปิดอยู่
- หากผู้ใช้ไม่ได้เปิดแอปพลิเคชันเลยเป็นเวลาหลายวัน ระบบควรทำการรีเซ็ตข้อมูลย้อนหลังให้เป็น 0 ของแต่ละวันโดยอัตโนมัติทันทีที่เปิดแอป หรือจะนับเฉพาะวันที่เปิดใช้งานจริง?
